# 스크립트 아키텍처

## 확정 구조

- `CGameScript`는 `CComponent`를 상속한다.
- `CGameObject`는 스크립트와 일반 컴포넌트를 하나의 `std::vector<SafePtr<CComponent>>`에 표시 순서대로 보관한다.
- 스크립트의 실제 메모리는 씬의 스크립트 타입별 타입 소거 풀에 있고, 오브젝트는 풀 객체의 안전 참조만 가진다.
- `CScriptSystem`은 오브젝트 계층 순서와 각 오브젝트의 컴포넌트 리스트 순서대로 `CGameScript`만 골라 라이프사이클을 호출한다.
- 일반 컴포넌트는 라이프사이클을 갖지 않으며 각 시스템이 타입별 풀을 순회한다.
- `GetOwner()`는 `SafePtr<CGameObject>`를 반환한다. 소유 오브젝트가 필요한 내부 코드는 `TryGet()`으로 접근한다.

## 메모리와 수명

- 씬 로드 분석은 스크립트 타입별 참조 수를 계산하고 기본적으로 사용량의 1.5배를 예약한다.
- DLL의 구체 스크립트 타입은 호스트가 컴파일 시 알 수 없으므로 일반 템플릿 컴포넌트 풀이 아닌 타입 소거 풀을 사용한다.
- 생성된 실제 스크립트 객체에는 `CComponent`의 안전 포인터 제어 블록을 연결한다.
- 제거, 씬 종료, 라이브 컴파일 언로드 시 입력 등록 해제, `OnDestroy`, DLL 소멸 함수, 풀 반환, 안전 포인터 무효화 순서를 지킨다.

## 에디터와 직렬화

- 컴포넌트 목록에서 스크립트는 일반 컴포넌트와 같은 순서 변경, 복사, 제거 계약을 사용한다.
- 스크립트 선택은 추가 시점에만 일어난다. 추가된 인스턴스의 타입을 바꾸는 콤보는 제공하지 않는다.
- YAML은 기존 호환을 위해 `Type: Script`와 `ScriptType`을 사용하지만, 로드 결과는 실제 `CGameScript` 컴포넌트다.
- 라이브 컴파일은 필드와 컴포넌트 순서를 스냅샷으로 보존한 뒤 새 DLL의 실제 스크립트 컴포넌트를 재생성한다.

## 검증 계약

- 같은 오브젝트에 같은 스크립트 타입을 여러 번 추가할 수 있다.
- 스크립트 실행 순서는 인스펙터 컴포넌트 목록 순서와 일치한다.
- `Rigidbody2D`, `Camera2D`, `AudioListener` 등 단일 컴포넌트 제한은 리플렉션 multiplicity로만 처리한다.
- Windows 에디터와 Web 런타임이 같은 공개 SDK 계약을 사용한다.
