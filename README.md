# JBroEngine

C++20으로 직접 만든 2D 게임 엔진입니다. 에디터, 렌더러, 물리, 오디오, 네트워크를
외부 게임 프레임워크 없이 구현했고, **Windows(Direct3D 11)와 Web(WebGPU)을 같은
프로젝트로 빌드**합니다. 게임 로직은 DLL로 분리된 C++ 스크립트로 작성하며, 에디터에서
컴파일하면 바로 반영됩니다.

플랫폼·디바이스 계층은 인터페이스로 추상화하고 검증된 라이브러리를 백엔드로 물렸습니다 —
오디오는 `IAudioDevice` 뒤에 **miniaudio**(미지원 환경은 무음 디바이스로 폴백),
텍스트는 **FreeType + HarfBuzz**, 에디터 UI는 **Dear ImGui**입니다. ImGui는 에디터
전용이라 패키징된 게임 빌드에는 포함되지 않습니다. 그 위의 오디오 버스·이펙트·에셋,
도킹 툴과 에디터 워크플로는 직접 구현했습니다.

## Canvas
<img width="1275" height="713" alt="engine4" src="https://github.com/user-attachments/assets/1e6d90e8-ad6f-4ffa-9086-87cfe17c66f0" />

씬에 해당하는 최상위 단위입니다. 오브젝트와 레이어를 소유하고, 코루틴 스케줄러와
물리 시스템도 캔버스마다 따로 돕니다.

**멀티 뷰포트** — 카메라는 "월드 속의 눈"일 뿐이고, *화면 어디에 / 어떤 레이어를*
그릴지는 캔버스가 가진 뷰포트 목록이 정합니다. 뷰포트 하나는 `카메라 참조 × 출력 렉트 ×
레이어 필터`로, 이 조합만으로 아래가 전부 표현됩니다.

- **분할 화면** — 좌/우 렉트 뷰포트 2개 + UI 레이어만 그리는 풀스크린 뷰포트 1개
- **미니맵** — 우상단 소형 렉트에 월드 레이어만
- **일반 게임** — 기본 뷰포트 1개(카메라 미지정 시 첫 활성 카메라로 폴백)

출력 렉트는 정규화 비율과 픽셀 오프셋을 함께 받아서 해상도가 바뀌어도 레이아웃이
유지되고, 레이어 필터는 인덱스가 아니라 GUID라 에디터에서 레이어 순서를 바꿔도
어긋나지 않습니다.

**캔버스 전환 시 레이어 유지** — 레이어를 `.jlayer` 파일로 분리해두면, 다음 캔버스로
넘어갈 때 같은 파일에서 온 레이어를 파괴하지 않고 인스턴스째 물려받습니다. 플레이어
오브젝트와 스크립트 상태가 무손상으로 넘어갑니다. 유지 여부는 *받는 캔버스 쪽* 설정이라
같은 레이어라도 던전은 유지, 보스전은 리셋처럼 따로 저작할 수 있습니다.

## Layer
<img width="1275" height="713" alt="engine3" src="https://github.com/user-attachments/assets/f15d2dc5-6a8d-4967-bda4-a3e28e6e0d95" />

캔버스의 합성 단위이자 오브젝트 그룹입니다. 트랜스폼이 없고 합성 속성만 가지며,
캔버스 안에서의 순서가 곧 아래→위 합성 순서이자 스크립트 실행 순서입니다.

**블렌드 모드** — `Normal` / `Additive` / `Multiply` / `Screen`. 포토샵식 기본셋을
렌더러가 RHI 블렌드로 매핑합니다. 레이어 단위 `Opacity`(0~1)를 함께 곱해서 페이드
연출을 레이어 통째로 걸 수 있습니다.

**월드 공간 / 화면 공간** — 레이어가 카메라를 따르는지, 화면에 못박히는지를 고릅니다.

- `World` — 카메라를 따릅니다. `ParallaxFactor`로 추종 배율을 줘서 원경을 절반 속도로
  흘리거나(0.5) 월드 원점에 고정(0)할 수 있습니다.
- `Screen` — 카메라와 완전히 무관합니다. 위치·회전·줌 전부 독립이라 UI/HUD가 여기에
  들어갑니다.

패럴랙스 0과 화면 공간은 다릅니다. 패럴랙스는 카메라 뷰의 *위치만* 배율하기 때문에
0으로 둬도 카메라가 줌하면 같이 커지고 회전하면 같이 기울어집니다. 그래서 보간 가능한
float이 아니라 별개의 선택지로 뒀습니다.

**화면 공간 스케일 모드** — 창 크기와 종횡비가 변할 때 "1 유닛이 몇 픽셀인가"를 정합니다.
`FixedHeight`(기준 높이 유지) / `FixedWidth`(세로 게임용) / `Contain`(기준 렉트 전체가
항상 보임, 잘림 없음) / `ConstantPixel`(픽셀 퍼펙트 UI). 데스크톱 패키지 창도 리사이즈
가능하므로 모바일 전용 옵션이 아니라 전 플랫폼 공용 저작 속성입니다.

## Physics
<img width="1275" height="713" alt="engine2" src="https://github.com/user-attachments/assets/3258c1fe-23ee-4751-947c-9969e0bc63f0" />

2D 강체 물리를 직접 구현했습니다. 고정 스텝으로 돌며 시퀀셜 임펄스로 접촉을 풉니다.

**강체와 콜라이더** — `Static` / `Kinematic` / `Dynamic` 바디, 질량·관성·마찰·반발·감쇠와
축별 이동/회전 고정. 콜라이더는 폴리곤과 원 두 종류이고, **오목 폴리곤은 Ear Clipping으로
볼록 조각들로 분해**한 뒤 조각 단위 SAT로 판정합니다. 정점 수만 바꾸면 삼각형부터 N각형까지
절차적으로 생성되고, 필요하면 정점을 직접 편집할 수도 있습니다.

**접촉 품질** — 매니폴드마다 접촉점에 Feature ID를 붙여 다음 스텝의 매니폴드와 매칭하고,
누적 임펄스를 복원하는 워밍 스타트를 씁니다. 마찰 클램프가 매 스텝 0에서 다시 시작하지
않아 물체가 경사면에서 미끄러지지 않고, 쌓아 올린 물체도 흔들리지 않습니다.

**충돌 필터** — 콜라이더마다 32비트 레이어/마스크를 가지며 `(A.Layer & B.Mask) &&
(B.Layer & A.Mask)`일 때만 충돌합니다. 트리거 판정도 지원합니다.

**조인트** — `DistanceJoint2D` 하나로 막대·로프·스프링을 전부 표현합니다(주파수 0이면
강체 구속, 0보다 크면 Hz 단위 스프링). `HingeJoint2D`는 두 점을 붙이고 회전만 남겨
문 경첩·바퀴 축·래그돌 관절이 됩니다. 상대를 비워두면 앵커를 월드 고정점으로 해석해서
천장에 매단 진자 같은 구성이 바로 나옵니다. 조인트는 접촉과 **같은 속도 반복 루프**에서
풀리기 때문에 둘이 서로를 밀어내지 않습니다.

**질의 API** — 게임플레이에서 바로 쓰는 형태로 제공합니다.

- 레이: `Raycast`(최근접) / `RaycastAll`(경로상 전부, 거리순 — 관통 판정)
- 오버랩: `OverlapPoint` / `OverlapCircle` / `OverlapBox`(회전 박스)
- 스윕: `CircleCast` / `BoxCast` — 폭을 가진 이동 판정(캐릭터 지면·벽 체크)

전부 레이어 마스크를 받고, 오버랩 결과는 오브젝트 단위로 중복이 제거됩니다.

## Light
<img width="1275" height="713" alt="engine1" src="https://github.com/user-attachments/assets/79531fcb-f5e6-43b0-a2cc-e0c5d824bd7b" />

2D 라이팅과 그림자입니다. 라이트는 컴포넌트 하나로 세 종류를 지원합니다.

- **Directional** — 방향광. 뷰포트 전체에 균일하게 들어갑니다.
- **Point** — 점광. 월드 위치를 중심으로 `Range`까지 반경 감쇠합니다.
- **Spot** — 원뿔광. 반경 감쇠에 `Inner`~`Outer` 각도 감쇠를 곱해 경계가 부드럽게
  퍼지는 원뿔을 만듭니다.

색상과 세기는 라이트마다 따로 주며, 여러 개를 겹쳐 쌓을 수 있습니다.

**그림자** — 그림자를 드리우는 스프라이트의 **알파 실루엣**을 월드 공간 오클루더 맵에
모아 그린 뒤, 라이트마다 그림자 아틀라스의 한 행을 채워 라이트 쿼드를 그릴 때 참조합니다.
스프라이트 모양 그대로가 차폐물이 되기 때문에 콜라이더를 따로 만들 필요가 없습니다.
`ShadowSoftness`(0~1)로 하드 경계부터 부드러운 반그림자까지 조절하고, Directional은
`ShadowLength`로 도달 거리를 끊어 태양 고도가 낮을수록 길게 늘어지는 유한 그림자를
만듭니다.

## Live-Compile
<img width="1275" height="713" alt="engine5" src="https://github.com/user-attachments/assets/ab8fb750-2a5b-49ec-826b-b289f649d357" />

에디터를 켜둔 채로 C++ 게임 스크립트를 고치고 저장하면, 빌드 후 DLL이 교체되어 그대로
이어집니다. 에디터를 다시 켜지 않아도 되고, 편집 중이던 캔버스도 그대로 유지됩니다.

**저장하면 알아서 빌드** — 소스 디렉터리를 파일 워처가 감시하다가 변경을 잡으면 디바운스
(기본 0.5초) 후 빌드를 겁니다. 컴파일은 **백그라운드에서 비동기로** 돌고 에디터는 그동안
멈추지 않습니다. 결과는 메인 스레드에서 폴링해 DLL 교체까지 처리합니다. 상태는
`Idle / Compiling / Loaded / Failed` 로 노출되고, 실패하면 컴파일러 메시지를 그대로
띄운 뒤 **직전에 로드된 DLL을 계속 씁니다** — 오타 하나로 작업이 끊기지 않습니다.

**스크립트 값이 살아남습니다** — 리로드 직전 모든 스크립트 인스턴스의 노출 필드 값을
스냅샷으로 찍고, 새 DLL을 로드한 뒤 되돌려 놓습니다. 오브젝트를 주소가 아니라 **GUID로
식별**하기 때문에 DLL이 통째로 갈려도 어느 오브젝트의 어느 컴포넌트였는지 정확히 찾아갑니다.
인스펙터에서 맞춰둔 수치가 리로드마다 초기화되지 않습니다.

**프로젝트 파일이 항상 따라옵니다** — 빌드 직전 훅에서 스크립트 프로젝트를 재생성합니다.
헤더에 `JBRO_SCRIPT` 로 선언된 클래스와 `JPROP` 으로 표시한 프로퍼티를 스캔해서 vcxproj와
등록 코드를 다시 써내기 때문에, 스크립트 파일을 추가·삭제하거나 프로퍼티를 넣고 빼도
프로젝트 설정을 손댈 일이 없습니다. 새로 만든 스크립트는 다음 빌드에 자동으로 에디터
목록에 올라옵니다.

**PDB 잠금 회피** — 빌드마다 중간 산출물 경로에 스탬프를 붙여 4슬롯으로 회전시킵니다.
매 빌드가 같은 PDB 경로를 노리면 직전 빌드로 로드된 DLL의 PDB를 디버거가 쥐고 있어
링커가 실패(LNK1201)하는데, 재사용되는 슬롯은 4빌드 전 것이라 이미 풀려 있습니다.
오래된 스탬프 폴더와 DLL은 최근 것만 남기고 정리하며, 잠긴 파일은 건너뜁니다.
