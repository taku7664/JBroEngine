# 레이어 계획

캔버스 레이어의 남은 기능을 모아 둔다. 레이어 선택·인스펙터·블렌드·불투명도(D-279), 3D 레이어(D-280), 블렌드 열셋(D-283)은 섰다.
이 문서는 그다음 - 기존 엔진에서 옮길 것과, 포토샵식 레이어에서 더할 것 - 의 목록과 단계다.

## 1. 기존 엔진의 레이어 (`C:\Users\박주형\source\repos\JBroEngine`)

`CGameLayer`(`Engine\GameFramework\Canvas\GameLayer.h:117-148`)의 필드와 우리 쪽 상태다.

| 기존 | 무엇 | 우리 |

| `Visible` | 렌더만 끈다 | 섰다 |
| `Space`·`ScaleMode` | 화면 레이어 | 섰다(D-237) |

| `KeepOnCanvasChange` | 런타임 캔버스 전환 때 받는 캔버스가 이 레이어를 이어받는다(`CanvasSerializer::TransitionFromText`) | **막힘** - 아래 |
| `ForceOwnTexture` | 늘 렌더 타깃을 거친다. 주석은 "차후 레이어 이펙트용" 이고 그림은 달라지지 않는다 | 해당 없음 - 레이어 효과가 생길 때 |

| 런타임 레이어 불러오기 | `CCanvasManager::RequestLayerLoad` 로 `.jlayer` 를 실행 중에 얹는다 | **막힘** - 아래 |

**막힘: 런타임 캔버스 전환이 없다.** 우리 엔진에는 스크립트가 캔버스를 바꾸는 길도, 실행 중에 레이어를 얹는 길도 없다(`git grep` 으로 확인 - 에디터의
캔버스 열기뿐이다). `KeepOnCanvasChange` 와 런타임 레이어 불러오기는 그 기능(새 서비스)과 함께 정한다. 에디터에서 캔버스를 여는 것은 기존 엔진에서도 통째로
갈아 끼우는 것이라 이어받기가 없었다(`AssetHandler.cpp:53-63`).

기존 엔진에서 보이는 고칠 것(조사 결과, 옮기지 않는다):
- 패럴랙스 레이어를 화면↔월드로 바꿀 때 계수 1 의 카메라로 옮겨 오브젝트가 튄다(`EditorLayerCommands.cpp:38-135`). 우리는 그 레이어의 계수로 옮긴다.
- 썸네일은 레이어 창이 있는 동안 모든 레이어를 매 프레임 다시 그렸다(요청을 프레임마다 비우는 줄이 빠졌다, `ImEditor.cpp:1048` 와 견줌).
- `.jlayer` 의 오브젝트 GUID 를 그대로 되살려 같은 에셋을 한 캔버스에 두 번 넣을 수 없었다. 우리 캔버스 파일은 오브젝트를 파일 안 번호로 적으므로(D-233)
  넣을 때마다 새 오브젝트이고, 안의 참조는 파일 번호로 이어진다 - 두 번 넣어도 된다.
- 레이어 삭제를 되돌리면 `SourceAssetGuid` 를 잃었다(`LayerPropertySnapshot` 에 없다). 우리는 같이 뜬다.

## 2. 패럴랙스

- 값은 캔버스의 `Layer` 가 든다(D-237·D-279 와 같은 자리). `Layer2D` 의 죽은 `parallaxFactor` 는 지운다. 파일 키는 `Parallax`(기본 1 이면 적지 않는다).
- **식은 기존 엔진과 같다**: 그 레이어를 그리는 뷰의 카메라 위치만 계수배. 회전·줌·뷰포트는 그대로 - 계수 0 도 화면 고정이 아니다(화면 고정은 화면 레이어다).
  같은 그림을 "그 레이어의 스프라이트를 월드에서 `카메라 위치 x (1 - 계수)` 만큼 옮긴 것" 으로 그린다 - 뷰를 레이어마다 열지 않고 브리지가 자리만 옮긴다.
- 게임 화면(게임 뷰·게임 빌드)과 썸네일에만 건다. **캔버스 뷰는 걸지 않는다**(기존 엔진과 같다 - 배치하는 자리이고, 고르기·기즈모가 그 그림과 맞는다).
- 버튼의 포인터 판정(`Button2DSystem::PixelToLayer`)과 레이어 공간 바꾸기(`MakeLayerSpaceCommand`)가 같은 셈을 쓴다. 물리·조명은 레이어를 모른다(기존과 같다).
- 화면 레이어는 계수를 보지 않는다. 인스펙터는 월드 레이어에만 칸을 보인다.

## 3. 레이어 에셋 `.jlayer`

- 에셋 타입 `Layer`, 확장자 `.jlayer`. 본문은 캔버스 파일과 같은 YAML 로 레이어 노드 하나와 그 레이어의 오브젝트(부모는 파일 안 번호)다. 레이어 노드는 캔버스 파일의
  `Layers` 항목과 **같은 함수**로 쓰고 읽는다 - 두 길이 갈리면 같은 레이어가 저장한 곳에 따라 다르게 읽힌다(기존 엔진 `LayerSerializer.h:10-11` 의 경고).
- 저장: 계층의 레이어 줄을 에셋 브라우저(빈 곳·폴더)에 끌어다 놓는다(기존과 같다). 레이어 메뉴의 `에셋으로 저장` 도 같은 일을 한다. 저장하면 그 레이어의
  원본 에셋이 그 파일이 된다(커맨드 - 되돌리면 표시가 빠진다. 파일은 남는다 - 에셋 브라우저의 파일 일은 따로 되돌린다).
- 넣기: `.jlayer` 를 계층에 끌어다 놓으면 맨 위에 새 레이어로 선다(기존과 같다). 커맨드 하나이고 되돌리면 그 레이어가 오브젝트째 빠진다.
- 원본 에셋(`SourceAsset`)은 캔버스 파일의 레이어 항목에 적고, 인스펙터가 읽기 전용 에셋 칸으로 보인다. 내용의 연결은 없다 - 레이어를 고쳐도 파일은 그대로다
  (기존과 같다). 레이어 삭제의 되돌리기는 원본 에셋도 되살린다.

## 4. 레이어 썸네일

- 그 레이어만 켠 게임 화면의 축소판이다(기존과 같다): 게임 카메라, 패럴랙스 적용, 블렌드·불투명도·보임은 무시, 불투명한 어두운 바탕. 크기는 줄 높이 두 줄에
  프로젝트 화면비. 계층의 레이어 줄 앞에 그린다.
- **매 프레임 다 그리지 않는다.** 계층 창이 보이는 프레임만, 한 프레임에 레이어 몇 장씩 돌아가며 그린다(기존 엔진은 창이 있는 동안 전부를 매 프레임 그렸다).
- 텍스처는 레이어마다 하나이고 계층 창이 그리지 않게 되거나 크기가 바뀌면 놓는다.
