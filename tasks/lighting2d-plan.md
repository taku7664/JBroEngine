# 2D 라이팅 계획 (라이트·그림자)

결정은 D-291. 2026-10-06 사용자 지시 "라이트 작업", 타입은 엔진 값 타입만(D-290). 이 브랜치(`lighting2d`)는 타입 전환 브랜치
(`claude/engine-value-types`) 위에서 시작했다 - main 의 리플렉션은 아직 `Float` 필드를 모른다.

## 1. 기존 엔진 (2026-10-06 읽음, `C:\Users\박주형\source\repos\JBroEngine`)

기존 엔진은 참고일 뿐 계약이 아니다. 무엇이 있었고 무엇이 틀렸는지만 적는다.

- **컴포넌트.** `Light2D`(`Directional`·`Point`·`Spot`, 색·세기·`Range`·안팎 각도·`CastShadows`·`ShadowLength`·`ShadowSoftness`).
  가림막 컴포넌트는 없고 `SpriteRenderer2D.CastShadow` 가 스프라이트 알파를 가림막으로 썼다. 환경광은 코드 상수 하나(`RuntimeConfig.AmbientLight`).
- **패스(`RenderWeave`).** 장면 → 가림막 맵(첫 카메라로 한 장) → 라이트마다 256 칸 극좌표 그림자 행(256 걸음 레이 마칭, RGBA8) → 라이트맵(RGBA16F,
  환경광으로 지우고 라이트 사각형을 더함) → 장면 × 라이트맵 → Reinhard 톤맵 → 화면 레이어를 얹음.
- **틀린 것(코드로 확인).**
  L1. 가림막 맵이 첫 카메라 하나로만 그려져 화면 밖 가림막은 그림자를 드리우지 않는다 - 화면 끝에서 그림자가 튄다.
  L2. 그림자 거리가 RGBA8 이라 256 단계이고, 걸음이 `Range/256` 이라 넓은 라이트에서 얇은 가림막을 놓친다.
  L3. 각도 축 표본기가 Clamp 라 θ=±π 에 이음매가 난다.
  L4. 톤맵이 노출 없이 Reinhard 라 빛 1 아래의 흰 스프라이트가 0.5 로 나온다.
  L5. `ShadowLength` 는 아무 데도 쓰이지 않고, Directional 은 그림자도 방향도 없다(화면 전체에 같은 색).
  L6. Vulkan 에서는 라이트·톤맵·축소 파이프라인을 건너뛰어 라이팅이 조용히 사라진다.
  L7. 레이어마다 빛을 끌 길이 없다. 화면 레이어만 빛을 받지 않는다.
  L8. 가림막 안에 둔 라이트는 제 가림막에 가려 꺼진다. 라이트를 화면과 견주어 고르지 않는다.
- **에디터.** 인스펙터는 리플렉션 그대로(각도는 라디안), 기즈모는 인스펙터에서 그 탭을 볼 때만 그렸고 끌 수 없었다. 캔버스 뷰는 빛 없이 그렸다.

## 2. 설계

### 2.1 정한 것 (2026-10-06 사용자 확인)

- 컴포넌트는 `Light2D` 와 `ShadowCaster2D` 둘이다.
- 그림자는 **도형 기반**이다. `ShadowCaster2D` 의 모양(같은 오브젝트의 콜라이더, 없으면 스프라이트 사각형)의 변을 라이트에서 밀어내 그리고,
  반그림자는 셰이더가 변 끝의 각도로 셈한다 - 해상도·이음매·화면 밖 문제(L1~L3)가 없다. 투명한 픽셀의 모양은 따르지 않는다.
- 빛을 받는지는 **레이어의 `lit`** 이 정한다. 월드 레이어는 기본으로 켜고, 화면 레이어는 늘 받지 않는다. 라이트는 빛을 받는 모든 레이어를 비춘다.
  사용자가 짚은 것: 라이트마다 대상 레이어를 고르는 것도 레이어를 차례로 그리므로 앞 레이어의 라이트맵을 이어 쓰면 크게 비싸지 않다 - 필요해지면 그 길로 더한다.
- 렌더 패스 그래프(공용 todo)를 기다리지 않는다. 라이트맵 패스는 레이어 합성 타깃(D-279)처럼 `RecordViews` 안에 하나 더 둔다.

### 2.2 렌더러

- **라이트 제출.** 뷰 안에서 `SubmitLight2D(Light2DSubmit)` - 종류·월드 위치·방향·색×세기·반지름 둘·각도 둘. 화면 좌표가 아니라 월드다.
- **라이트맵.** 라이트가 하나라도 있고 빛을 받는 스프라이트가 있는 뷰는 메인 패스 전에 타깃과 같은 크기의 **RGBA16F** 라이트맵을 그린다.
  `Global` 라이트의 합으로 지우고, `Point`·`Spot` 은 한 번의 인스턴스 드로우로 더한다(`One·One`). 1 을 넘는 빛도 담는다.
  프레임 안에서 자원을 만들지 않으므로 레이어 타깃처럼 바라는 크기로 적고 다음 프레임에 만든다 - 없는 프레임은 빛 없이 그린다.
- **빛을 받는 스프라이트.** `SetSpriteLighting(Bool)` 이후 낸 스프라이트는 빛을 받는다(레이어 묶음처럼 구간으로 기록). 그 구간은 픽셀 셰이더가
  라이트맵을 화면 자리(`SV_Position / 타깃 크기`)에서 읽어 색에 곱한다. **따로 합성하지 않는다** - 레이어 묶음(D-279)·아래 그림 블렌드(D-283)와
  순서가 그대로 맞고, 톤맵이 없어 빛 1 아래의 흰색은 흰색이다(L4). 뷰에 라이트가 없으면 빛을 받는 구간도 그대로 그린다(라이팅 꺼짐).
- **그림자(3 단계).** 그림자를 드리우는 라이트는 하나씩: 그림자 마스크를 지우고 가림막 변을 인스턴스(변 하나 = 끝점 둘)로 밀어내 그린 뒤, 마스크를 읽으며
  그 라이트를 더한다. 변 데이터는 인스턴스 버퍼로 넘긴다 - 상수·구조화 버퍼(공용 todo)를 기다리지 않는다. 푸시 상수는 Vulkan 128 바이트 안이다.

### 2.3 프레임워크

- `Light2D`: `type`(`Global`·`Point`·`Spot`)·`color`(`Color`)·`intensity`(`Float`)·`innerRadius`·`outerRadius`(`Float`)·`innerAngle`·`outerAngle`(`Degree`)·
  `castShadows`(`Bool`)·`shadowSoftness`(`Float`). 방향은 오브젝트 회전이다.
- `ShadowCaster2D`: `shape`(`Collider`·`Sprite`), `selfShadow`(`Bool`) - 가림막 안의 라이트가 꺼지는 것(L8)을 고른다.
- `Layer::lit`(`Bool`, 기본 참). 캔버스 파일의 `Lit`, 레이어 인스펙터의 칸.
- 수집 시스템이 라이트를 `RenderWorld2D` 에 담고, 다리(`RenderBridge2D`)가 월드 뷰에 낸다. 편집 화면도 같은 라이트로 그린다.
