# 3D 조명 계획 (Light3D)

결정은 D-407. 2026-11-19 사용자와 정했다(todo-3d 우선순위 5, "다 추천안대로"). 그림자는 이 계획에 없다 - 그 뒤의 일이다.

> 상태: **완료** (2026-11-19 시작·세 단계 완료, D-408~D-410). 남은 것은 §4.

## 1. 지금 상태와 참고한 것

### 1.1 지금 엔진 (2026-11-19 실측)

- 3D 의 빛은 `BuiltinMesh.hlsl` 의 상수 셋이다: 고정 방향광(`normalize(0.4, 0.8, 0.45)` 쪽으로, 세기 0.75)과 주변광 0.25. `Standard` 재질(D-399)이
  그 빛으로 metallic-roughness PBR 을 셈하고, `Unlit` 은 빛을 받지 않는다.
- 메시 패스는 b0 푸시 상수(뷰-투영·카메라 위치·탄젠트 있음)와 b1 재질 상수 블록을 묶는다. 렌더러는 프레임마다 바뀌는 상수를 올리는 `ConstantRing`(D-325)을
  아직 쓰지 않는다.
- 2D 는 `Light2D`(종류 `Global`·`Point`·`Spot`, 색·세기·반지름 둘·전체 각 둘·그림자)와 렌더러의 `SubmitLight2D` 가 섰다(D-291, `lighting2d-plan.md`).
  라이트는 레이어를 가리지 않고 빛을 받는 모든 레이어를 비추며, 감춘 레이어의 라이트는 꺼진다. 캔버스에 라이트가 없으면 라이팅이 꺼진 장면이다.

### 1.2 상용 엔진과 glTF (2026-11-19 조사)

| | 종류 | 거리 감쇠 | 원뿔 각 | 환경광 | 라이트가 없을 때 |
|---|---|---|---|---|---|
| glTF `KHR_lights_punctual` | directional·point·spot | `clamp(1 - (d/range)^4, 0, 1) / d^2`, `range` 없으면 무한 | 가운데에서 잰 반각, 기본 안 0·밖 π/4 | 없음 | - |
| Unity (URP) | Directional·Point·Spot·Area | Range 로 자름 | Inner/Outer Spot Angle(원뿔 전체) | Lighting 창(라이트가 아님) | 새 씬에 방향광이 들어 있음 |
| Unreal | Directional·Point·Spot·Rect·Sky | 기본 거리 제곱, Attenuation Radius 는 자르기만 | 안/밖 원뿔 | SkyLight 컴포넌트 | - |
| Godot 4 | DirectionalLight3D·OmniLight3D·SpotLight3D | `omni_attenuation` 지수(기본 1, 2 가 물리) | spot_angle·spot_angle_attenuation | `WorldEnvironment` | **에디터만** 미리보기 해·환경을 띄우고, 씬에 방향광을 놓으면 끈다 |

- 물리 단위(루멘·럭스)는 Godot·Unreal 모두 켜는 설정이고 기본은 단위 없는 배율이다.
- 라이트 수: Unity URP 포워드는 오브젝트당 추가 라이트 8, Forward+ 는 데스크톱 카메라당 256.
- 출처: KHR_lights_punctual README(Khronos), Godot 문서(GLTFLight·OmniLight3D·물리 단위·환경), Unreal 문서(Point Light·`bUseInverseSquaredFalloff`),
  Unity 문서(Light 컴포넌트·Forward+·라이트 제한). Filament 문서는 읽지 못했다(리디렉트).

## 2. 설계 (D-407, 2026-11-19 사용자 확인)

### 2.1 정한 것

1. **컴포넌트 `Light3D` 하나에 종류.** `Ambient`·`Directional`·`Point`·`Spot`. 2D 의 `Light2D` 와 같은 모양이고 2D 의 `Global` 이 3D 의 `Ambient` 다.
   세 엔진 모두 환경광은 라이트 종류가 아니지만(Unity 는 설정, Godot 는 `WorldEnvironment`, Unreal 은 따로 된 SkyLight), 2D 와 같은 모양을 앞에 둔다.
   하늘 상자 같은 환경이 오면 그때 다시 본다(§4).
2. **거리 감쇠는 glTF 권장식, 필드는 `range` 하나.** 2D 의 안·밖 반지름과 다르다 - 선형 감쇠는 PBR 과 섞이면 어색하고, glTF 와 같으면 모델의 라이트를 그대로 가져온다.
   `range` 가 0 이면 무한(감쇠는 거리 제곱만)이다. 거리는 0.01 아래로 내려가지 않는다(라이트 바로 곁의 무한대 방지).
3. **라이트가 없는 캔버스는 지금의 고정 빛이다.** "라이트가 없으면 라이트 기능 전과 같다" 는 2D 규칙과 같은 뜻이다. Godot 는 에디터에서만 이렇게 하지만,
   여기는 게임도 같다 - 에디터와 게임이 같은 그림을 내는 것을 시험이 바이트로 본다(D-404). `Light3D` 가 하나라도(종류 무관) 뷰에 오면 놓인 라이트만 빛을 낸다.
   새 3D 프로젝트의 시작 오브젝트(`AddStarterObjects`)에 `Directional` 라이트 하나를 더한다.
4. **포워드, 뷰마다 라이트 목록 하나.** 상수 블록(b2)에 `Ambient` 합과 라이트 최대 64 를 담아 픽셀마다 모두 돈다. 넘치면 버리고 센다
   (`RendererFrameStats`, 2D 의 `maxLights2D` 와 같은 꼴). 클러스터는 재 본 뒤다.
5. **그림자는 하지 않는다.** `castShadows` 필드도 그림자 단계에서 더한다 - 하는 일 없는 필드를 두지 않는다.

### 2.2 컴포넌트 `Component::Light3D`

| 필드 | 타입 | 기본 | 뜻 |
|---|---|---|---|
| `type` | `Light3DType` | `Point` | `Ambient`·`Directional`·`Point`·`Spot` |
| `color` | `Color` | 흰색 | 선형 |
| `intensity` | `Float` Clamp(0, 100) | 1 | 색에 곱한다. `Directional`: 마주 보는 흰 램버트 면이 이 값이 된다. `Point`·`Spot`: 1 유닛 거리에서 그렇다(거리 제곱 감쇠) |
| `range` | `Float` Clamp(0, 1000) | 10 | `Point`·`Spot`. 여기서 0. 0 이면 무한 |
| `innerAngle` | `Degree` Clamp(0, 179) | 30 | `Spot` 원뿔 **전체** 각(2D 와 같다). 안은 다 닿는다 |
| `outerAngle` | `Degree` Clamp(0, 179) | 60 | 여기서 0 |

- 자리와 방향은 오브젝트의 `Transform3D` 월드 값이다. 빛은 로컬 -Z 로 간다(glTF·`AudioListener3D` 와 같다). 크기는 보지 않는다.
- 원뿔 감쇠는 glTF 식: `t = saturate(cos θ · scale + offset)`, `scale = 1 / max(0.001, cos(안/2) − cos(밖/2))`, `offset = −cos(밖/2) · scale`, 빛 × t².
  안 각이 밖 각보다 크면 같다고 본다.
- 감춘 레이어의 라이트는 꺼진다(2D 와 같다). 라이트는 모든 레이어의 메시를 비춘다. `Unlit` 재질과 발광은 영향을 받지 않는다.

### 2.3 렌더러

- `Light3DSubmit`(종류·월드 위치·방향·색×세기·`range`·전체 각 둘)과 `SubmitLight3D(s)` - 뷰 안에서 받는다(2D 와 같은 자리). `Ambient` 는 뷰의 환경광에 더하고
  나머지는 뷰의 목록에 담는다. 상한은 `RendererConfig::maxLights3D`(기본 64, 셰이더 배열 길이와 같다).
- 메시 패스는 뷰마다 라이트 블록을 `ConstantRing` 에 한 번 올려 b2 로 묶는다. 라이트를 받지 않은 뷰는 렌더러가 **기본 빛**(지금의 고정 방향광·주변광)을 그 블록에 채운다 -
  셰이더는 길이 하나다.
- 블록: `float4 ambientCount`(rgb 환경광, w 라이트 수) + 라이트마다 `float4` 넷(자리와 `range`, 방향과 종류, 색, 원뿔 scale·offset) = 16 + 64 × 64 = 4112 바이트.

### 2.4 프레임워크와 스크립트

- `Light3DSystem` 이 `RenderWorld3D` 에 라이트를 담고, 브리지가 뷰마다 같은 목록을 낸다(레이어마다 뷰가 열리므로).
- 스크립트 핸들 `Light3D`(2D 의 `Light2D` 핸들과 같은 멤버).

### 2.5 에디터 (2D 와 같게)

- 컴포넌트 추가 메뉴·인스펙터는 리플렉션 그대로. 끝이 안전장치일 뿐인 값은 끌기다(2D 와 같은 `Clamp`).
- 캔버스 뷰: 라이트 오브젝트에 전구 표시(빛의 색), 고르면 `Point` 는 `range` 구, `Spot` 은 원뿔과 각 손잡이, `Directional` 은 방향 화살표. 손잡이로 `range`·각을 끈다.

## 5. 그림자 (D-445, 2026-11-22)

사용자와 정한 것(2026-11-21, "ㅇㅇ"): 방향광 → 스포트 → 점광 차례, 방향광은 캐스케이드 넷을 2048 칸에 넣고 3x3 PCF 와 깊이·법선 바이어스, 그림자 거리 50,
`Light3D` 에 `castShadows`·`shadowStrength`, `MeshRenderer3D` 에 `castShadows`·`receiveShadows`(둘 다 기본 켬), 처음 상한은 그림자를 드리우는 방향광 하나·스포트 넷, 반투명은 드리우지 않는다.

### 5.1 선 것

- `[완료]` **컴포넌트**: `Light3D::castShadows`(기본 꺼짐 - 새 3D 프로젝트의 시작 해만 켠다)·`shadowStrength`(0..1), `MeshRenderer3D::castShadows`·`receiveShadows`(기본 켬).
  렌더 항목·시스템·브리지가 렌더러의 `Light3DSubmit`·`MeshSubmit` 의 같은 칸으로 옮긴다. 인스펙터는 반사 표에서 저절로 칸을 낸다.
- `[완료]` **아틀라스**: 4096 x 2048 깊이 한 장(`D32Float`, `DepthStencil | Sampled`), 칸은 1024. 왼쪽 2 x 2 가 방향광의 캐스케이드 넷, 오른쪽 2 x 2 가 스포트 넷이다.
  → D-446 으로 4096 x 4096 이 되었다 - 이 배치는 위 절반이고 아래 절반이 점광의 면이다.
  장치는 프레임 안에서 자원을 만들지 않으므로 그림자를 처음 바란 프레임은 그림자 없이 그리고 다음 `BeginFrame` 이 만든다. 3D 그림자를 쓰지 않으면 만들지 않는다.
- `[완료]` **캐스케이드**: 카메라 앞 `CameraParams::shadowDistance`(기본 50)까지를 고른 것과 로그를 0.75 로 섞어 넷으로 나눈다. 조각마다 화면 네 모서리의 가까운·먼 점 사이를
  깊이 비율로 이어 여덟 점을 얻고, 그 점들을 덮는 공(반지름을 1/16 로 올림)에 맞춘 직교 투영이다. 중심은 라이트 평면에서 칸 크기로 맞춰 옮긴다 - 카메라가 움직여도 그림자 가장자리가 떨지 않는다.
  라이트 쪽으로 50 더 물러서서 보이지 않는 곳의 물체도 그림자를 드리운다(`CasterReach`).
- `[완료]` **스포트**: 원뿔보다 0.05 라디안 넓은 원근(가까운 면 0.05, 먼 면은 `range`, 없으면 100).
- `[완료]` **그리기**: 뷰마다 메시가 있고 그림자를 드리우는 라이트가 있으면 본 패스 앞에 깊이 전용 패스 `Shadow` 하나가 칸마다 뷰포트를 바꿔 그림자를 드리우는 묶음을 그린다(양면, 메시 정점 단계에
  라이트의 뷰-투영을 밀어 넣는다). 묶음은 정렬 열쇠의 46·47 비트로 받기·드리우기가 갈린다(메시 자리는 22 비트). 반투명 묶음은 그리지 않는다.
- `[완료]` **읽기**: 표준 머티리얼(`Standard`)이 b3 의 그림자 블록과 t5 의 아틀라스를 읽는다. 카메라 깊이로 캐스케이드를 고르고, 면의 법선 쪽으로 칸 1.5 개만큼 밀고, 3x3 PCF 를 `Load` 로 한다
  (RHI 에 비교 샘플러가 없다). 깊이 바이어스는 방향광 0.0005, 스포트 0.00002 다. 짙기만큼 그 라이트의 빛을 줄인다. 받지 않는 메시는 푸시 상수 w 의 2 로 알린다.
- `[완료]` **RHI**: 색 첨부 없는 깊이 전용 파이프라인과 렌더 패스를 세 백엔드가 받는다(깊이는 있어야 한다). D3D11 의 기본 시저는 깊이 텍스처 크기다.

- `[완료]` **점광**(D-446, 2026-11-22): 상용 엔진과 견준 뒤 사용자가 "권고안대로" - 진짜 큐브맵(RHI 의 큐브·배열 텍스처)도 듀얼 패러볼로이드도 아니고,
  큐브의 면 여섯을 같은 아틀라스에 2D 칸으로 넣는다(Unity URP 가 스포트·점광 아틀라스에 점광 하나를 여섯 칸으로 넣는 것과 같은 모양). 아틀라스를 4096 x 4096 으로 늘려
  아래 절반에 512 칸 스물넷(점광 넷 x 여섯 면, 한 줄에 여덟)을 둔다. 면은 +X·-X·+Y·-Y·+Z·-Z 차례이고, 시야각은 90 도에 반 칸에서 4 텍셀의 여유를 더한 것이라
  (약 90.9 도) 면 가장자리의 3 x 3 PCF 가 칸 안의 깊이를 읽는다. 셰이더는 법선으로 민 점에서 라이트까지 방향의 가장 큰 축으로 면을 고르고, 바이어스는 스포트의 것,
  민 거리는 스포트처럼 거리 x 칸 크기 x 1.5 다. 먼 면은 `range`(없으면 100), 가까운 면 0.05.
  **거르기**: 메시마다 경계 공(정점 상자의 가운데·가장 먼 정점)을 올릴 때 재고, 묶음마다 인스턴스의 공을 월드로 옮긴 상자를 모은다. 점광의 면은 빛의 공(위치, `range`)과
  겹치지 않는 묶음을 그리지 않는다. 면마다 원뿔 거르기는 하지 않았다.
  시험: `MeshPixel` 의 `TestShadowsFallBehindMeshes` 끝(세 백엔드) - (0, 2.5, 0) 의 점광 아래 납작한 판, 바닥의 x = 2.3·2.5·2.7(-Y 면·경계·+X 면)이 그림자이고
  같은 x 의 z = 1.5 는 밝다. 짙기 0.5 와 끈 라이트도 본다.

## 6. 환경 - 환경광·하늘·반사 (D-447, 2026-11-23)

사용자와 정한 것(2026-11-23, 상용 엔진과 견준 권고에 "권고안대로 확정하고 전부 진행"): 환경은 **캔버스 설정**이다(Unity 의 Lighting 창 Environment 자리). 캔버스 하나에 환경 하나라
"둘이면 무엇이 이기나" 가 없고, 캔버스가 최상위 실행 단위다(Godot 의 `WorldEnvironment` 노드·Unreal 의 Sky Light 컴포넌트는 고르지 않았다 - 둘을 놓을 수 있어 규칙이 필요하다).
`Light3D` 의 `Ambient` 는 지우지 않고 그 위에 더해지는 평평한 빛으로 남는다(2D 의 `Global` 과 같은 모양, 옛 캔버스·시험이 그대로). 단계는 색·그라디언트 → 하늘 배경과 SH 확산광 → 반사다.

### 6.1 선 것

- `[완료]` **자료**: `CanvasEnvironment`(`JBroCanvas`) - `ambientSource`(`Color`·`Gradient`·`Sky`), `ambientColor`, `skyColor`·`equatorColor`·`groundColor`(Unity 새 씬의 기본값),
  `ambientIntensity`(0..8), `skyId`(하늘 맵 에셋)·`skyIntensity`(0..8)·`skyRotation`(도, +Y 둘레), `reflectionIntensity`(0..1). 기본은 검은 `Color` 에 하늘 없음 - 환경 전과 같은 그림이다.
  `.jcanvas` 에 `Environment` 로 적히되 **기본이면 적지 않는다**(옛 파일과 글자까지 같다). 출처는 이름으로 적고 모르는 이름·아이디가 아닌 하늘은 거절한다. `Canvas::Clear` 가 기본으로 되돌린다.
- `[완료]` **하늘 맵 에셋**: `.hdr`(Radiance RGBE, 등장방형)이 새 에셋 종류 `EnvironmentMap` 이다. stb_image 의 HDR 디코더(`DecodeHdrImage`)가 선형 빛으로 풀고, 8 비트 그림은 하늘로 받지 않는다.
  게임 빌드는 캔버스의 `skyId` 를 함께 싣는다(`CollectCanvasAssetIds`).
- `[완료]` **굽기**(`EnvironmentMap.h`, 렌더러를 모르는 CPU 셈): 그림을 256 x 128 로 맞춰 밉 0(거울)으로 두고, 아래 다섯 단계(128 x 64 ~ 8 x 4)는 거칠기 0.2·0.4·…·1 의 GGX 로 미리 거른다
  (Karis 2013 의 N = V = R 가정, 표본 64, 표본의 입체각에 맞는 원본 밉에서 읽는 Colbert·Křivánek 2007 의 필터드 중요도 표본 - 원본 피라미드는 16 x 8 에서 멈춘다, 더 거친 텍셀은 반대편 빛을 끌어온다).
  확산광은 밉 0 을 입체각으로 적분한 SH 9 계수다(조도 / π, Ramamoorthi·Hanrahan 2001). 무한·NaN·음수 텍셀은 0 으로 굽는다(잘린 파일의 쓰레기가 SH 전체를 덮었다). `RGBA16Float` 2D 텍스처 하나에 밉 여섯이다.
  **RHI 는 그대로다** - 큐브 텍스처 대신 등장방형 2D 의 밉 체인이다(입력이 등장방형이고 가로 반복으로 경도의 이음매가 없다. 극 쪽은 텍셀이 촘촘해 낭비가 있다).
- `[완료]` **프레임워크**: `EnvironmentLibrary`(`Framework3DSystem`)가 갱신 끝(렌더러 프레임 밖)에 캔버스 환경을 렌더러의 `Environment3D` 로 푼다 - 색에 세기를 곱하고, 하늘은 같은 에셋·같은 자료 세대면
  다시 굽지 않는다(세기를 바꿔도 굽지 않는다). 렌더 월드가 들고 브리지가 뷰마다 `CameraParams::environment` 로 싣는다.
- `[완료]` **렌더러**: 표준 머티리얼(`Standard`)이 b4(환경 블록 240 B)·t6(하늘 맵)·s1(가로 반복·세로 멈춤 - 세로까지 돌면 바로 위를 읽을 때 맨 아래 줄이 섞였다)로 읽는다.
  확산 = 출처의 빛(`Color` 색·`Gradient` 의 법선 높이 섞기·`Sky` 의 SH) x 기본색 x (1 - metallic) x 차폐. 반사 = 반사 방향의 빛(`Sky` 는 거칠기 x (밉 수 - 1) 단계의 하늘 맵, 나머지는 그 색) x
  표 없는 split-sum BRDF(Karis 2014 모바일 근사) x 차폐 x `reflectionIntensity`. `Ambient` 라이트의 옛 항(기본색 x 차폐, metallic 무시)은 그대로다.
- `[완료]` **하늘 배경**: `Camera3D::background`(`Color`·`Sky`). `Sky` 면 브리지가 레이어 뷰 앞에 하늘만 그리는 뷰를 연다 - 하늘은 레이어가 아니라 배경이라 블렌드 레이어 아래에 그대로 있다.
  프로그램 `Sky` 는 정점 번호로 덮는 삼각형 하나, 역 뷰-투영으로 가까운·먼 점을 풀어 방향을 낸다(직교 카메라는 한 방향). 캔버스 뷰는 하늘 맵이 있으면 늘 하늘을 그린다(Unity 의 씬 뷰). 썸네일은 그리지 않는다.
- `[완료]` **에디터**: 3D 캔버스의 인스펙터에 `환경` 절(출처에 맞는 칸만), 고치기는 환경 전체를 뜬 `SetCanvasEnvironmentCommand`(칸마다 합치기 열쇠). 에셋 브라우저의 하늘 맵은 지구 아이콘.
- 시험: `Environment`(방향·자리 왕복, 고른 하늘의 SH·밉, 위만 밝은 하늘 1·0.5·0, 밝은 점의 번짐과 반대편 0, 쓰레기 텍셀, `.hdr` 디코드, `.jcanvas` 왕복·기본은 적지 않음·모르는 출처 거절),
  `MeshPixel` 의 `TestEnvironmentLightsMeshes`(세 백엔드 - 색·세기·그라디언트·하늘 확산 0.1 의 절대값·세기 0·거울 금속의 반사·반사 0·하늘 배경·한 번만 굽기·종료 때 텍스처 해제),
  에디터 `TestTheCanvasEnvironmentIsEditedIn3D`(커맨드·되돌리기·저장과 다시 열기, 스크린숏 `canvas_environment`).

### 6.2 `[열림]`

- 하늘 회전은 픽셀로 보지 않았다 - SH·배경·반사가 같은 함수(`RotateIntoSky`)를 쓴다.
- 셰이더 머티리얼(D-347)과 `Unlit` 은 환경을 받지 않는다. 스크립트에서 환경을 바꾸는 서비스가 없다.
- 반사는 하늘 하나뿐이다 - 반사 프로브(방 안·지역마다의 반사)·화면 공간 반사는 없다. 그림자 진 곳에도 하늘 빛이 그대로 든다(환경광 차폐는 재질의 차폐 그림뿐).
- 하늘 맵 굽기는 메인 스레드에서 한 번이다(디버그 빌드로 256 x 128 에 1 초 안팎으로 추정, 재지 않았다). 큰 `.hdr` 의 디코드도 같다. 워커로 옮길지는 재 본 뒤다.
- 하늘이 없을 때 `Sky` 배경은 지우기 색이다(그라디언트 하늘을 그리지 않는다). 절차적 하늘(태양 위치로 그리는 하늘)은 없다.
- 등장방형 2D 라 극 근처는 텍셀이 촘촘하다. 큐브맵이 필요해지면(반사 프로브 등) RHI 에 큐브를 들이고 바꾼다.
