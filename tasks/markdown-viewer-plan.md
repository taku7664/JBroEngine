- 이미지 경로는 문서 폴더 기준이며 기존 ImageDecoder/RHI로 표시한다. 에셋 등록이나 .jmeta 쓰기를 하지 않는다.
- 엔진 값 타입·컨테이너·공용 테마·로컬라이징·위젯·행동·패널 등록 규칙을 적용한다. 파서와 서드파티 타입은 내부 경계에만 둔다.

## 구현 연결

- `Document/Markdown`은 MD4C 콜백에서 블록·서식·본문·링크·이미지·앵커를 만든다. HTML은 원문으로 남기며 선언 문자열/정규식 파서는 없다. 엔티티와 원문 포인터를 이용한 코드 선행 탭 보존을 처리한다.
- `Widget::MarkdownView`는 한 글자 배치에서 본문·표·코드·이미지의 선택/검색/그리기를 처리한다. 폭·글꼴 변경 시 배치만 갱신하고 화면 밖 글자는 그리지 않는다. 코드 색상은 `CodeHighlighting`의 기존 언어/팔레트와 vendor의 읽기 전용 스냅샷을 사용한다.
- `MarkdownPanel`은 전용 문서 독의 InstancePanel이다. 기존 행동 표, 루트/패널 파일 메뉴, 명령 팔레트, 경로 선택 요청을 사용한다. Ctrl+O는 바꾸지 않았다. 같은 경로는 기존 탭으로 이동하고 탭 표시/포커스 전환 때 파일 시각을 확인한다.
- 파일 스트림은 메인에서 준비하고 Task의 worker는 값 버퍼 읽기·파싱·디코드만 수행한다. main 완료 콜백에서 스트림을 닫고 버전이 맞는 결과만 적용한다. 완료 이력이 CPU 데이터/핸들을 보관하지 않도록 반환 뒤 버퍼도 비운다. GPU 업로드는 RHI 프레임 밖 main 경로이고, 파기는 기존 썸네일 큐를 공용화한 프레임 번호 기반 퇴역 경로다. 문서 종료는 취소→대기→텍스처 해제 순서다.
- 이미지 경로·플랫폼 열기는 패널에만 있다. PNG/JPEG/BMP/TGA 디코더와 RHI를 재사용하며 에셋/메타 파일을 만들지 않는다. 엔진 값 타입/컨테이너/소유권을 사용한다. 외부 파서·글꼴/그리기 API의 원시 값은 해당 경계에만 있다.
- 공용 테마는 기존 글꼴 메모리 로딩을 공유하고 본문/코드 글꼴에 보충 문자 글꼴을 합친다. 패널 안에 직접 ImGui 호출이나 별도 메뉴 스타일은 없다. 실제 화면은 빌드와 별도로 확인한다.

## 검증 중 발견하고 수정한 항목

1. MD4C가 앞쪽 탭을 펼치던 코드 복사 결과: 파서가 제공한 원문 위치의 공백 구간으로 보존했다.
2. 루트 파일 메뉴가 확장 행동을 자동 표시하지 않던 부분: 기존 `DrawItem` 경로로 `markdown.open`을 명시 배치했다.
3. 검색 입력을 Enter 때만 반영하고 이동 버튼을 화면 밖으로 밀던 부분: 공용 검색 위젯의 정상 변경 통지와 폭을 사용한다. 입력란의 Enter 해제와 결과 이동도 정식 키 입력 회귀로 확인한다.
4. 탭 표시와 키보드 포커스의 차이 및 중복 포커스 요청: 두 활성화 변화를 확인하고 선택한 문서의 다른 미처리 요청을 정리한다.
5. 완료 태스크 이력의 열린 스트림/큰 버퍼 보관: main 완료 콜백에서 바로 해제하고 완료·취소 뒤 단독 파일 열기와 8회 반복을 검사한다.

6. 같은 프레임의 그림 그리기 뒤 문서 파기: `close-frame-repro.log`의 정식 렌더링 회귀에서 실패를 재현했다. 기존 레이어 썸네일 퇴역 큐를 `RetireUiTexture`로 공용화하고 ImGui 프레임 번호를 기록해 현재 그리기 목록의 텍스처를 같은 프레임에 무효화하지 않는다. 별도 큐/관리자를 추가하지 않고, 종료는 강제 해제·장치 상실은 핸들 폐기로 처리한다. `close-frame-fixed.log`에서 같은 회귀가 통과했다. 공용 큐에 닿는 기존 `EditorApplication` 묶음도 추가 실행하여 통과했다.
