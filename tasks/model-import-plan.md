# 모델 임포트 계획 (D-338)

> 상태: **진행** (2026-11-16 시작, 1 단계 완료). todo-3d 우선순위 3. 사용자와 토론해 정한 것(2026-11-16): 가져오는 단위는 메시가 아니라 **모델**,
> 디코더는 **ufbx + cgltf**("범용적인 걸 쓰되 하나로 안 되면 여럿 허용"), 하위 에셋은 에셋 브라우저에서 **▶ 로 펼친다**(그림의 Texture·Sprite 도 같이),
> 모델에 **내장된 같은 그림은 자동으로 묶되 묶인 것을 보이게** 한다. 에디터 화면은 2D 를 따르고, 3D 만의 것이라 달라야 하면 먼저 묻는다.

## 1. 지금 있는 것 (2026-11-16 실측)

- 확장자 표(`AssetTypeRules.cpp`)가 `.obj .gltf .glb` 를 `Mesh` 로 안다. 읽는 코드는 없다 - `AssetSystem::Load` 는 메시에 빈 핸들이다.
- `MeshLibrary`(Framework3DSystem)가 빌트인 도형 다섯을 렌더러에 올리고 `AssetId → AssetHandle` 을 든다(D-337). 스프라이트의 `SpriteLibrary` 와 같은 자리다.
- 렌더러의 메시 정점(`MeshVertex`)은 위치·법선뿐이다(24 바이트, 셰이더 ABI). UV 는 재질 때 붙는다(todo-3d 우선순위 4).
- 레지스트리의 `AssetRecord::owner` 가 이미 "이 레코드는 저 에셋에서 나왔다" 를 적는다 - 그림 파일 하나가 Texture 와 Sprite 두 레코드가 되고
  `.jmeta` 하나에 두 아이디가 든다(D-111). 모델의 하위 에셋은 같은 틀이다.
- 에셋 브라우저는 그림을 **한 칸**으로 보인다. 짝 Sprite 는 펼쳐지지 않고 끌 때 함께 실릴 뿐이다(`AssetBrowserPanel` 의 `paired`).
- 2D 그림의 흐름: 브라우저로 가져오기(복사 + `.jmeta`) → 디코드는 워커(D-236), 풀은 메인 → GPU 는 라이브러리 → 컴포넌트 칸에서 고름 →
  옵션은 `.jmeta` 의 `ImportOptions` 를 브라우저에서 고침 → 파일 감시로 다시 읽음. 모델도 이 흐름이다.

## 2. 설계

### 2.1 단위와 하위 에셋

- 파일 하나(`.fbx .gltf .glb .obj`)가 **Model** 에셋 하나다. 새 `AssetType::Model` 을 두고 확장자 표에서 네 확장자를 `Model` 로 바꾼다.
  `Mesh` 는 하위 에셋의 타입으로 남는다(빌트인 도형도 `Mesh` 다).
- 하위 에셋: 파일 안의 메시마다 **Mesh**, 재질마다 **Material**, 내장 그림마다 **Texture**. 모두 `owner` 가 Model 이고 경로는 Model 의 경로다.
- **하위 아이디는 `.jmeta` 에 이름으로 고정한다.** 키는 `종류/파일 안의 이름`(이름이 없거나 겹치면 `종류/번호`)이다. 다시 가져와도 같은 키면
  같은 아이디라 캔버스의 참조가 끊기지 않는다. 사라진 키의 아이디는 버리고, 새 키는 새 아이디를 받는다.
- 메시 칸 목록에는 `Character.fbx / Body` 처럼 모델 경로와 하위 이름으로 보인다.

### 2.2 디코더

- **ufbx**(FBX·OBJ, MIT, C 파일 하나)와 **cgltf**(glTF 2.0 `.gltf`·`.glb`, MIT, 헤더 하나). 둘 다 STL 을 쓰지 않는다. `ThirdParty/` 에 판을 고정해 둔다.
  Assimp 는 형식이 넓지만 크고(C++·STL·CMake) FBX 최신판·애니메이션에서 자주 틀려 고르지 않았다. FBX SDK 는 소스가 닫혔고 재배포·Web 이 막혀 쓰지 않는다.
- 디코더는 `JBroAsset` 의 `ModelDecoder` 하나 뒤에 숨는다. 확장자로 ufbx·cgltf 를 고르고, 결과는 엔진 값 타입의 CPU 자료(`ModelData`)다 -
  메시마다 정점(위치·법선·UV)·인덱스·재질 번호, 재질마다 이름·기본색·텍스처 칸(번호), 그림마다 바깥 경로 또는 내장 바이트, 노드 계층과 변환.
- 좌표: glTF 는 엔진과 같은 오른손·Y 위·미터라 그대로다. FBX·OBJ 는 ufbx 의 축·단위 변환(`target_axes`·`target_unit_meters`)으로 엔진 좌표에 맞춘다.
- 법선이 없으면 계산해 채운다. 삼각형이 아닌 면은 디코더가 삼각형으로 나눈다.
- **선 모양(2 단계)**: 두 디코더는 "삼각형 꼭짓점 목록"(합치지 않음, 파일의 반시계 감김)을 내고 공통 마무리가 법선(옵션)·배율·감김 뒤집기(엔진은 바깥에서 볼 때 시계)·
  정점 합치기(바이트로 정렬해 이웃끼리)를 한다. 메시 하나 = 재질 하나라 glTF 의 프리미티브·FBX 의 재질 부분마다 `ModelMesh` 하나이고 이름은 `메시/재질` 이다(겹치면 ` (2)`).
  정점은 메시 자신의 좌표다 - ufbx 의 축·단위·기하 변환은 정점에 굽고(`MODIFY_GEOMETRY`), 노드 변환은 `ModelNode` 에 따로 든다. FBX·OBJ 의 UV 는 세로를 뒤집는다(아래가 0 → 위가 0).
  디코더는 파일을 열지 않는다(D-112) - `.gltf` 의 바깥 버퍼와 OBJ 의 `.mtl` 은 `ModelFileReader` 로 받는다(ufbx 는 `load_external_files` 를 켜야 `.mtl` 을 읽고, 없으면 재질만 빠진다).
  법선 계산은 같은 자리 꼭짓점 가운데 면 법선이 `smoothingAngle` 안에 드는 면들의 넓이 가중 합이다. 법선을 다시 계산하면 파일의 탄젠트는 버린다.
  cgltf 구현은 `fopen`·`strncpy` 경고(C4996, SDL 이 오류로 올린다)를 내서 그 include 동안만 경고를 끈다 - 서드파티는 고치지 않는다.

### 2.3 첫 판의 범위

- **메시**: 그려지는 데까지(메시 풀 → `MeshLibrary` → `MeshRenderer3D` 의 메시 칸). 첫 판은 **파일 하나 = 메시 여럿(하위 Mesh)** 을 칸에서 고른다.
  모델을 계층에 끌어 노드 트리째 놓는 것(프리팹 같은 것)은 프리팹이 없어 뒤다 - 그때 3D 만의 화면이라 먼저 묻는다.
- **재질·텍스처**: 하위 에셋으로 읽어 브라우저와 목록에 보이는 데까지. 재질 칸에 걸어 화면에 쓰는 것은 재질 구현(우선순위 4) 때 잇는다.
- 애니메이션·뼈대는 하지 않는다.

### 2.4 텍스처

- **바깥 그림 파일을 가리키면** 그 그림은 이미 일반 Texture 에셋이다(2D 와 같다). 하위 Material 이 그 아이디를 적는다. 프로젝트 밖에서 가져온 모델이면
  그림도 함께 복사한다(2D 의 가져오기와 같다).
- **모델 안에 내장된 그림**은 Model 의 하위 Texture 다. 디코드는 지금의 이미지 디코더(stb_image)에 메모리 바이트를 넘긴다 - 새 디코더가 없다.
- 색 공간은 재질의 어느 칸에 쓰였는지로 정한다(기본색 sRGB, 노멀·거칠기 따위 선형). 옵션에서 바꾼다.
- 여러 메시가 한 텍스처를 쓰는 것은 복사가 아니라 같은 아이디를 가리키는 것이다(메시 → 재질 → 텍스처). 파일 안에서도 텍스처는 재질이 번호로 가리키는
  따로인 객체라, 파일 안의 그림 하나가 하위 Texture 하나다.

### 2.5 내장 그림의 자동 묶기와 표시

- 서로 다른 모델에 **같은 그림이 각각 내장**되면 하위 Texture 는 둘이지만 실체는 하나로 묶는다. 기준은 **원본 바이트의 해시(64 비트)와 실제로 적용되는
  임포트 옵션(색 공간·필터·밉맵)이 둘 다 같을 때**다. 해시는 가져올 때 `.jmeta` 에 적고, `AssetSystem` 이 "해시 + 옵션" 을 키로 이미 읽은 것을 다시 쓴다 -
  디코드와 GPU 업로드가 한 번이다. 한쪽 옵션을 바꾸면 키가 달라져 저절로 갈라진다.
- 둘은 동등하다. 대표·참조로 나누지 않는다(대표를 든 모델을 지우면 소유를 옮겨야 한다).
- **보이게 한다**: 브라우저의 펼친 하위 Texture 줄(아이콘 보기는 타일 모서리)에 고리 아이콘과 수(`2`), 툴팁은 같은 그림인 에셋들. 인스펙터에서 그 Texture 를
  고르면 `같은 그림` 줄에 묶인 에셋들, 누르면 브라우저에서 보인다. 묶인 Texture 의 옵션을 고치면 칸 아래에 "바꾸면 따로 읽는다" 를 안내한다(막지 않는다).
  통계 패널에 묶은 수와 아낀 메모리 한 줄(선택).
- 실제 메모리 공유는 텍스처가 GPU 에 쓰이는 재질 단계에서 붙는다. 첫 판은 해시 기록·배지·`같은 그림` 줄까지다.
- 바깥 그림 파일은 원래 에셋 하나라 묶을 것이 없다.

### 2.6 에셋 브라우저의 ▶ 펼치기

- 하위 에셋이 있는 것은 모두 ▶ 로 펼친다 - 모델과 **그림(Texture·Sprite)도**. 목록 보기는 트리, 아이콘 보기는 타일 옆에 하위 타일이 이어 붙는다(Unity).
  하위 에셋도 끌어다 칸에 놓는다.
- **화면을 먼저 보인다** - 자료를 잇기 전에 펼친 모양을 시험 화면(`JBRO_EDITOR_SHOT`)으로 찍어 사용자 확인을 받는다(사용자: "예쁘게 못 만들 것 같아서 무서운데").
- 모델을 두 번 누르면 여는 임포트 설정·3D 미리보기 창(Godot 식)은 뒤다 - 2D 의 스프라이트 뷰어 자리다. 3D 미리보기는 3D 만의 화면이라 할 때 묻는다.
- **선 모양(1 단계)**: 목록 보기는 계층 패널과 같은 트리 화살표이고 하위 줄은 화살표 한 칸만큼 들어가며 종류·날짜·아이디 열은 부모 줄과 맞춘다.
  아이콘 보기는 칸 오른쪽 가운데의 작은 단추(`>` 접힘·`<` 펼침, MDI `chevron-right`·`chevron-left`)이고, 펼친 파일 칸과 하위 칸이 한 덩어리의 밝은 띠(`FrameBgHovered`) 위에 선다.
  펼친 상태는 아이디로 기억하고 두 보기가 함께 쓴다. 화살표·단추로 펼치는 것은 고르기가 아니다. 하위 항목을 누르면 인스펙터가 그것을 보고 파일 선택은 비운다
  (남겨 두면 하위를 본 채 Delete 로 부모 파일이 지워진다). 하위 항목을 끌면 아이디만 싣는다(폴더에 놓아도 아무것도 옮겨지지 않는다). 두 번 누르면 부모 파일을 두 번 누른 것과 같다.
  하위 항목의 이름은 지금 종류(`Sprite`)다 - 모델의 메시·재질은 3 단계에서 파일 안의 이름을 갖는다.
  펼침 단추는 칸보다 **먼저** 낸다: 칸 뒤에 커서를 옮겨 단추를 냈다가 되돌리면 ImGui 가 "커서를 옮긴 뒤 항목 없이 창이 끝남" 으로 단언했다(시험이 잡았다).

### 2.7 임포트 옵션 (`.jmeta` 의 `ImportOptions`)

사용자와 추렸다(D-339): **비용이 싸거나 빠지면 결과가 틀리는 것**은 첫 판에 넣고, 비싸거나 쓰는 곳이 없는 것은 남은 일(§4)로 둔다.
스프라이트 옵션과 같은 자리(브라우저에서 고른 에셋의 인스펙터)에서 고치고 커밋으로 되돌린다.

- **`ModelImportOptions`**: `scale`(1.0, 단위를 바꾼 뒤 곱하는 배율) · `convertUnits`(켬, 파일의 단위를 미터로 - FBX 는 흔히 cm) ·
  `normals`(`Import` 파일의 것·없으면 계산 / `Calculate` 늘 다시 계산) · `smoothingAngle`(60°, `Calculate` 일 때만, 이보다 크게 꺾인 모서리는 각지게) ·
  `importMaterials`(켬, 끄면 재질·내장 그림 하위 에셋을 만들지 않는다).
- **`TextureImportOptions` 에 둘을 더한다**(모델 내장 그림과 일반 그림 공통): `colorSpace`(`Auto`·`Srgb`·`Linear` - `Auto` 는 재질의 기본색 칸이면 sRGB,
  노멀·거칠기 따위 칸이면 선형, 일반 그림은 sRGB) · `mipmaps`(모델 텍스처는 켬, 일반 그림은 끔 - 2D 픽셀 아트는 밉이 없어야 한다).
  **둘은 지금 값을 저장하고 인스펙터에 보이기만 한다(사용자 선택 (a))** - 효과(sRGB 텍스처 뷰·밉 체인 업로드)는 3D 가 텍스처를 처음 그리는 재질 단계(todo-3d 우선순위 4)
  에서 켠다. 그때 검증할 수 있어서다. 지금 2D 그림에는 아무 변화가 없다.
- **옵션이 아니라 늘 한다**: 정점 합치기와 인덱스 버퍼 만들기(ufbx 는 면마다 정점을 따로 준다), 인덱스 16·32 비트 자동(정점 65,536 미만이면 16),
  삼각형 나누기, 파일에 탄젠트가 있으면 CPU 자료에 읽어 두기(노멀맵 단계에서 다시 읽지 않는다).
- 축은 옵션이 아니다 - glTF 는 고정, FBX 는 파일이 말하고 ufbx 가 엔진 축으로 바꾼다, OBJ 는 Y 위로 가정한다(틀리는 파일이 나오면 `upAxis` 를 더한다).

### 2.8 하위 목록이 서는 길 (3 단계에서 정한 것, D-341)

- `.jmeta` 의 `Model:` 블록에 `ImportOptions` 와 `SubAssets`(항목마다 `Key: Mesh/Body`·`Id`)가 있다. 키는 `종류/이름` 이고 종류는 `Mesh`·`Material`·`Texture`(5 단계)다.
  키가 겹치거나 아이디가 모델·서로와 겹치면 메타 전체가 실패다.
- **게임은 메타의 목록만 본다** - 모델을 읽지 않고 하위 레코드를 세운다. **에디터는 목록이 없을 때만 모델을 읽어 채운다**(`RefreshModelSubAssets`) -
  프로젝트를 열 때마다 모든 모델을 다시 읽지 않는다. 같은 키는 아이디를 지키고 새 키는 새 아이디, 사라진 키는 빠진다. 키의 이름은 메시는 디코더의 메시 이름(`Crate/Wood` -
  재질로 나뉜 메시는 `메시/재질`), 재질은 재질 이름이고 겹치면 ` (2)` 를 붙인다.
- 읽히지 않는 모델도 모델 레코드는 선다(하위 에셋만 없다, 스캔 보고의 `unreadableModel`) - 브라우저에 보여야 고칠 수 있다.
- 옵션 편집은 하위 목록을 새 옵션으로 다시 맞춰 **같은 커맨드**(`SetAssetMetaCommand`)에 담는다 - 되돌리면 옛 목록과 옛 아이디가 돌아온다. 메타를 쓴 뒤 에디터가
  다음 프레임 앞에서 레지스트리를 다시 훑는다(`RequestAssetRescan` - 그리는 도중에 표를 바꾸면 패널이 든 레코드 포인터가 죽는다).
- 남은 것: 모델 **파일**이 바뀌었을 때 목록을 다시 맞추는 것은 파일 감시(4 단계)다. 지금은 메타를 지우거나 옵션을 고쳐야 다시 읽는다.

## 4. 열린 것 `[열림]`

- 모델을 계층에 끌어 노드 트리째 놓기(프리팹이 서야 한다) - 3D 만의 화면이라 할 때 묻는다.
- 모델 미리보기 창과 썸네일 렌더링 - 3D 만의 화면이라 할 때 묻는다.
- 텍스처 꺼내기(내장 그림을 파일로 풀어 일반 Texture 로).
- 정점 형식에 UV 를 더하는 것(재질 단계). 그때까지 UV 는 CPU 자료에만 있다.

**남은 일 - 옵션과 기능 (D-339 에서 미룬 것, 사용자: "남은 작업으로 둬")**

- `[남은 일]` `colorSpace`·`mipmaps` 의 **효과**: sRGB 텍스처 뷰, 밉 체인 만들기와 업로드, 샘플러. 재질 단계(우선순위 4)와 RHI 확장(D-322)에서. 옵션 값은 2 단계부터 저장된다.
- `[남은 일]` 탄젠트 **계산**(파일에 없을 때) - MikkTSpace 를 들여야 한다(서드파티, 확인 대상). 노멀맵 재질과 함께.
- `[남은 일]` 메시 최적화(정점 캐시 차례)·압축 - meshoptimizer 를 들여야 한다(서드파티, 확인 대상). 성능을 잰 뒤에.
- `[남은 일]` 라이트맵 UV - xatlas 를 들여야 한다(서드파티, 확인 대상). 라이트맵 계획과 함께.
- `[남은 일]` 읽기 가능(`readable`, CPU 사본 유지) - GPU 에 올린 뒤 CPU 사본을 버리는 경로와 함께. 메시 콜라이더(3D 물리, 우선순위 9)가 읽을 때.
- `[남은 일]` 애니메이션·뼈대·블렌드셰이프 가져오기 - 스켈레탈 애니메이션 단계.
- `[남은 일]` 카메라·조명·노드 계층 가져오기 - 모델을 노드 트리째 놓기(위 첫 줄)와 함께.
- `[남은 일]` `upAxis`(OBJ) - 축이 틀린 OBJ 가 실제로 나오면.
