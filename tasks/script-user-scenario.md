# 사용자 시나리오: 에디터를 켜서 스크립트를 쓰고 돌리기까지 (D-328)

> 2026-10-15 작성. 처음 쓰는 사용자(시나리오 A), 일부러 잘못 쓰는 사용자(시나리오 B), JBroScript 로 쓰는 사용자(시나리오 C)가 에디터를 켜서 스크립트를 만들고 돌리기까지의 흐름을 걸으며 적은 메모다.
> 문서를 보고 확신하지 않았다 - 화면으로 본 것은 **[봄]**, 코드로만 안 것은 **[코드]**, 확인하지 못한 것은 **[의문]**, 고친 것은 **[고침]** 으로 적는다.
> A·B 의 스크립트는 **C++**(`.h`·`.cpp`, `JBRO_SCRIPT_BODY`), C 는 **JBroScript**(`.jscript`)다. C 는 main 에 JBroScript 컴파일러와 빌드 타깃(`JBro.GameScript.targets` 가 `jbroc --emit-project` 로 C++ 을 만든다)이 들어온 뒤에 걸었다.
> 세 시나리오는 시험 묶음 `UserScenario`(`Tests/EditorApplicationTests.cpp` 의 `TestScenarioAFirstScript`·`TestScenarioBHostileUser`·`TestScenarioCJBroScript`)로 서 있고 모두 지난다.

## 1. 어떻게 걸었나

- 처음에는 실제 에디터 창을 띄워 메시지로 눌렀다. `새 프로젝트` 의 Windows 폴더 고르기 창을 밖에서 다루자 `파일 열기` 창이 또 떠 꼬였고, 이 길은 접었다.
- 그 뒤로는 시험이 사용자의 손을 대신한다. 폴더 고르기는 대화상자를 대신하는 함수가 답하고, 팝업에는 글자와 키를, 인스펙터에는 클릭을 넣는다.
  메뉴 항목은 메뉴가 부르는 것과 같은 함수(`RequestNewProject`·`OpenNewScriptPopup`·`BuildScripts`)나 행동 표(`object.create`·`simulation.play`)를 부른다.
  스크립트는 실제 MSBuild 로 빌드하고 실제 DLL 을 싣는다.
- `JBRO_EDITOR_SHOT` 에 폴더를 주면 단계마다 화면을 찍는다(`editor_a01_start.bmp` ~ `editor_b15_closed_mid_build.bmp`, 31 장). 아래 [봄] 은 그 그림이다.
- [의문] 대화상자를 대신하므로 네이티브 폴더 창의 모양은 보지 않았다. 메뉴를 마우스로 여는 길은 기존 시험이 보고, 이 시나리오는 보지 않는다.

## 3. 시나리오 B - 일부러 잘못 쓰는 사용자

한글 폴더(`사용자 폴더`) 아래에 한글 이름(`내 게임`)으로 프로젝트를 만들고 그 안에서 한다.

| 단계 | 하는 것 | 기대와 결과 |
|---|---|---|
| 1 | 폴더 고르기를 취소 | 아무것도 묻지 않고 돌아온다 |
| 2 | 빈 이름에 Enter | 만들지 않는다. 빈 이름은 글로 탓하지 않고 `만들기` 만 흐리다 |
| 3 | `a/b` | [고침] 치는 동안 `폴더 이름으로 쓸 수 없는 이름입니다` 가 뜨고 `만들기` 가 꺼진다(전에는 Enter 를 눌러야 알았다) |
| 4 | 이미 있는 폴더 이름 `Taken` | [고침] 치는 동안 `같은 이름이 이미 폴더에 있습니다` |
| 5 | `내 게임` | 만들어지고 열린다 |
| 6 | 스크립트 없이 빌드 | `스크립트를 빌드하지 못했습니다 - 스크립트 프로젝트가 없습니다. 에셋 브라우저의 스크립트에서 새 스크립트를 먼저 만드세요` |
| 7 | 스크립트 이름: 빈 것·`1Player`·`class`·`Transform2D`·`Player Mover`·`플레이어`·이미 있는 `Hero` | 모두 만들지 않고 까닭이 보인다. [고침] `Transform2D` 처럼 엔진 컴포넌트와 같은 이름을 막는다(전에는 만들어졌고, 프렐류드의 핸들 이름과 부딪혀 빌드가 깨질 자리였다) |
| 8 | Esc | [고침] 팝업이 닫힌다(전에는 이름 칸이 Esc 를 먹어 닫히지 않았다) |
| 9 | 빌드를 두 번 누른다 | 두 번째는 시작하지 않는다(단추가 `빌드하는 중..` 으로 막힌다) |
| 10 | 30 번째 `OnUpdate` 에서 null 에 쓰는 스크립트를 실행 | 실행이 멈추고 캔버스가 실행 전 글자와 같게 돌아온다. 알림: `스크립트 오류로 실행을 멈췄습니다 - 잘못된 메모리에 접근했습니다 - Hero.cpp:20 (OnUpdate). 눌러서 그 줄을 엽니다`(D-325) |
| 11 | 실행 중에 빌드 | `실행을 멈추면 새 스크립트를 불러옵니다`, 멈추면 싣는다 |
| 12 | 붙은 스크립트의 파일을 지우고 빌드 | 스크립트는 저장된 그대로 오브젝트에 남는다. [고침] `캔버스의 스크립트 1개를 찾지 못했습니다` 경고(전에는 성공 알림만 떴다) |
| 13 | 빌드 중에 프로젝트를 닫는다 | 빌드가 끝나고 에디터는 산다 |

## 3.1 시나리오 C - JBroScript 로 쓰는 사용자

C++ 사용자와 같은 길을 `.jscript` 로 걷는다. 걷기 전의 상태는 [코드]로 먼저 보았다 - 빌드 타깃은 `Scripts/**/*.jscript` 를 모아 C++ 로 바꿔 같이 컴파일하지만, 에디터는 `.jscript` 를 목록에 보이기만 하고 만들지 못했다.

| 단계 | 하는 것 | 기대와 결과 |
|---|---|---|
| 1 | 새 프로젝트 | [고침] 전에는 `Contents/Scripts` 폴더가 없었다. `.jscript` 를 편집기에서 바로 만들 자리가 없었다. 이제 새 프로젝트가 만든다 |
| 2 | `새 스크립트` 에서 `언어` 를 JBroScript 로 고르고 `Mover` | [고침] 전에는 팝업이 C++ 만 만들었다. 이제 `이름` 아래 `언어` 칩(C++ / JBroScript, 2D 프로젝트만)이 있고, 고르면 이름 칸으로 돌아가 바로 칠 수 있다. 고른 언어는 에디터를 켜 둔 동안 이어진다. `Mover.jscript` 하나(빈 `OnStart`·`OnUpdate`)가 생기고 `.h`·`.cpp` 는 없다. 만든 알림은 `OnUpdate` 본문 줄을 연다 |
| 3 | 만든 그대로 빌드 | 지난다 |
| 4 | `OnUpdate` 에 자기 `Transform2D` 의 `position` 을 `[prop] speed` 만큼 옮기는 코드를 쓰고 빌드 | 지난다. 생성된 C++ 은 프로젝트의 중간 폴더에만 있고 사용자 파일은 건드리지 않는다 |
| 5 | 컴포넌트 추가에서 `Mover` | C++ 스크립트와 같이 목록에 나오고 붙는다 |
| 6 | 실행 | 20 프레임에 x 가 2 넘게 움직이고, 멈추면 제자리다 |
| 7 | `speed` 를 `spped` 로 틀리게 쓰고 빌드 | [봄] `Mover.jscript(9) JBC3004 알 수 없는 이름입니다: spped` 하나가 `빌드 결과` 맨 위에 서고, 누르면 `.jscript` 의 그 줄이 열린다(생성된 C++ 이 아니다). [고침] 전에는 `jbroc` 가 실패 코드로 끝났다는 `MSB3073` 줄(긴 명령줄)이 오류로 하나 더 붙어 오류가 2 개로 셌다 |
| 8 | 고쳐 다시 빌드 | [고침] 전에는 고치기 전의 `빌드하지 못했습니다` 알림이 성공 알림 옆에 남았다. 이제 성공하면 닫힌다(C++ 도 같다) |
| 9 | 실행 중 `missing!.position.x = 1.0`(빈 ref 단언) | 그 콜백만 멈추고 실행은 이어진다(D-317 의 계약). [고침] 전에는 로그에만 매 프레임 쌓여 로그 탭을 열지 않으면 몰랐다. 이제 `스크립트 오류로 그 콜백을 멈췄습니다 - Mover.jscript:8 invalid ref assertion: missing! - 실행은 이어집니다. 눌러서 그 줄을 엽니다` 가 자리마다 실행 한 번에 한 번 뜬다 |

- [의문] `jbroscript-syntax.md` §9.1 은 "null 검사 없이 쓰면 컴파일 에러" 라고 하는데, `GetComponent<Transform2D>()` 의 결과를 검사 없이 `transform.position` 에 썼더니 빌드가 지났다. 시험 파일(`Control.jscript` 의 `MoveOwner`)도 같다. 문서가 옛것인지 컴파일러가 덜 막는지 확인하지 않았다.
- [의문] 문법 문서 §14 예시는 `fn OnUpdate() callback`(접근자 없음)인데 시험 파일은 모두 `public fn ... callback` 이다. 만들기 틀은 시험 파일을 따랐다.
- [의문] 실행 오류의 글(`invalid ref assertion: missing!`)은 런타임이 영어로 낸다. 에디터가 번역하지 않는다.
- [의문] JBroScript 예약어(`fn`·`script`·`ref` 등)를 이름으로 넣으면 이름 검사는 C++ 기준이라 통과하고 빌드에서 걸린다. 확인하지 않았다.
- [의문] 3D 프로젝트에서는 언어 줄을 두지 않는다(빌드 타깃이 2D 만 받는다). 3D 사용자가 `.jscript` 를 손으로 넣으면 빌드가 영어 오류로 거절한다.

## 4. 고친 것

| 무엇 | 전 | 후 |
|---|---|---|
| 에디터와 같이 뜨던 콘솔 창 | `SubSystem Console` 이라 런처·탐색기로 띄우면 검은 창이 같이 떴다(런처가 `CreateNoWindow` 없이 띄운다) | 창 프로그램(`SubSystem Windows`, 진입점 `main` 그대로). 터미널에서 띄우면 부모 콘솔에 붙고, 출력을 파일로 돌리면 그 파일로 간다(`ParentConsole.cpp`) |
| 새 프로젝트의 빈 캔버스 | 카메라가 없어 실행해도 `카메라가 없습니다` | 주 카메라 `Camera` 하나(2D 는 크기 5, 캔버스 뷰 처음 넓이와 같다) |

| 빌드 성공 | `빌드했습니다` + `다시 불러왔습니다` 두 알림(처음 싣는데도 "다시"), 인스펙터를 덮었다 | 하나: `스크립트를 빌드했습니다` - `인스펙터의 컴포넌트 추가에서 붙일 수 있습니다`. 미룸·실패·옮기지 못한 값은 따로 알린다 |
| 빌드 실패 | `빌드하지 못했습니다` 만 | 첫 오류의 파일:줄·코드·글을 보이고 누르면 그 줄을 연다 |
| 빌드 중 빌드 결과 칸 | 비어 멈춘 것처럼 보였다 | `스크립트를 빌드하는 중입니다...` |
| 인스펙터의 `Transform2D` | 월드 캐시(행렬 여섯 칸·월드 위치·회전·크기·유효)가 펼쳐져 아래 컴포넌트를 밀어냈다 | 모두 읽기 전용인 `Category` 는 접힌 한 줄(`월드 캐시`). 고칠 수 있는 필드가 섞인 분류(`AudioSource` 의 `Spatial`)는 그대로 |
| 새 프로젝트·새 스크립트 팝업의 이름 칸 | Enter 전까지 이름 값이 옛 것이라 검사·단추가 옛 이름을 보았다. 거절되면 칸의 포커스가 빠져 다시 누르고 쳐야 했다. 이름을 고쳐도 지난 오류가 남았다 | 치는 동안 이름을 옮기고(`TextField::LiveText`) 검사한다. 거절되면 칸으로 돌아간다. 오류는 그 이름일 때만 보인다 |
| 새 프로젝트 이름 검사 | `CreateProjectFile` 안에만 있었다 | `CheckProjectName` 으로 떼어 만들기와 팝업이 같은 검사를 쓴다 |

## 5. 남은 의문

- [의문] 메뉴 두 줄(`파일` 만 떨어진 줄)이 처음 사용자에게 메뉴로 읽히는가. D-134 의 결정이라 손대지 않았다.
- [의문] 새 프로젝트의 3D 카메라는 위치를 옮기지 않았다(축 방향을 확인하지 않았다). 빈 캔버스라 보이는 것이 없어 실측하지 못했다.
- [의문] 새 프로젝트는 캔버스 파일 없이 `캔버스 (저장 안 됨)` 으로 열린다. 저장하지 않고 닫으면 묻는다(D-324)지만, 처음부터 `Main.jcanvas` 를 둘지는 정하지 않았다.
- [의문] 두 라이브러리는 `AssetSystem::SlotMask`(private)를 볼 수 없어 같은 값을 따로 적었다. 핸들 배치를 다시 바꾸면 세 곳을 함께 고쳐야 한다 - 공개 상수나 `SlotOf()` 로 모을지 정하지 않았다.
- [의문] 알림은 오른쪽 아래에 쌓여 인스펙터 아래쪽을 덮는다. 실제 시간에서는 성공 알림이 5 초(만든 스크립트 안내는 8 초) 뒤 사라지지만, 겹치는 자리는 그대로다.
- [의문] 빌드가 도는 동안 진행률이나 컴파일 중인 파일은 보이지 않는다(cpp-script-plan §3.4 의 남은 일).
- 시나리오와 무관하게 찾은 것: main 의 `NodeGraphAddNode`(`node_graph.add_node`) 키는 노드 찾기가 `노드 추가` 하위 메뉴를 대신한 뒤(2f379a71) 쓰이지 않아 `EditorLocalization` 묶음이 실패했다. 키와 번역 둘을 지웠고, 전체 시험(101 묶음)이 한 번에 지난다.

## 6. 이 문서로 할 수 있는 것

- 흐름을 바꾸면 `JBRO_TESTS=UserScenario` 로 두 시나리오를 돌리고, `JBRO_EDITOR_SHOT` 을 주어 단계별 화면을 다시 본다.
- 새 실패 경우를 찾으면 시나리오 B 표에 줄을 더하고 같은 시험에 단계를 넣는다.
