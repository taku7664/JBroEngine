## 0. 한 줄 요약

기존 엔진의 `Text2D` 는 FreeType(SDF) + HarfBuzz 로 한글·라틴을 그렸지만, **HarfBuzz 를 글자 묶음 하나씩 불러서 커닝이

(3) 문자열은 컴포넌트 밖의 호스트 소유 저장소에 두고 핸들과 세대로 가리키는 것이다. 1 단계는 비트맵(커버리지) 글자라서

### 1.2 깨트려 본 결과 - 코드에서 확인한 결함

"이 구조가 최선이었나" 에 대한 답이다. 코드로 확인한 것과 계산으로만 추정한 것을 나눠 적는다.

1. **HarfBuzz 를 글자 묶음 하나씩 불러서 커닝과 합자가 적용되지 않는다.** (코드로 확인)
   `BuildLayout`(`:317~345`)은 코드포인트 하나를 읽고, 뒤따르는 결합 문자·자모만 붙인 뒤, 그 조각만 `ShapeRun` 에 넘긴다.
   HarfBuzz 는 넘겨받은 조각 안에서만 GPOS 커닝과 GSUB 합자를 적용하므로, `AV`·`To` 처럼 **두 글자 사이의 조정은 한 번도
   일어나지 않는다.** 결과적으로 HarfBuzz 는 "코드포인트 → 글리프 번호 + 전진 폭" 이상의 일을 하지 않았다. 큰 의존성을 들이고
   그 값어치를 쓰지 못한 자리다.
2. **줄바꿈이 단어가 아니라 글자 묶음 단위다.** (코드로 확인)
   `:337` 이 글자 묶음마다 폭을 넘는지 보고 바로 줄을 바꾼다. 영어 `hello` 가 `hel` / `lo` 로 갈린다. 공백에서 끊는 규칙이 없다.
   한국어는 글자 단위 줄바꿈도 흔히 쓰이지만, 어절 단위를 고를 수 없다.
3. **텍스트가 바뀔 때마다 GPU 버퍼를 새로 만든다.** (코드로 확인)
   `RebuildText`(`:432~535`)가 `Immutable` 정점·인덱스 버퍼를 새로 만든다(`:410~422`). 점수·타이머처럼 매 프레임 바뀌는 텍스트는
   프레임마다 버퍼 생성·파기가 일어나고, 그 전에 `std::string` 정규화 사본(`:285~299`), `std::vector` 여럿, `unordered_map` 하나를
   힙에 만든다. ProjectRule 의 "매 프레임 경로에 힙 할당 금지" 에 걸린다. 자동 크기는 이진 탐색 8 번이 모두 레이아웃을 새로 한다.
4. **변경 감지가 매 프레임 문자열 전체를 해시한다.** (코드로 확인)
   `OnUpdate` 가 텍스트마다 `BuildSignature`(`:424`)를 부르고, 그 첫 줄이 `std::hash<std::string>{}(text.Text)` 다. 바뀌지 않은
   텍스트도 매 프레임 글자 수만큼 돈다.
5. **캐시 키가 컴포넌트 주소다.** (코드로 확인)
   `m_textCache` 가 `const void*` 를 키로 쓴다(`:618`). 풀에서 파기된 자리에 새 컴포넌트가 오면 옛 캐시를 이어받는다. 시그니처가
   다르면 다시 만들어서 대개 드러나지 않지만, 같은 글자를 가진 새 오브젝트는 옛 메시와 경계를 그대로 받는다.
6. **렌더 시스템이 컴포넌트에 경계를 되써 준다.** (코드로 확인)
   `Text2D.h:18~23` 이 이것을 "경계 규약의 유일한 예외" 라고 적었다. 에디터의 클릭 선택과 외곽선이 렌더 시스템이 한 번 돈 뒤에야
   맞는 값을 본다. 생성 직후 프레임과 폰트가 없는 동안에는 빈 경계다.
7. **외곽선 폭의 상한이 글자 크기에 묶이고, 넘으면 사각형이 칠해진다.** (셰이더 식으로 확인, 수치는 추정)
   셰이더는 `outerThreshold = 0.5 - fwidth(d) * width` 다(`Forward2DRenderer.cpp:253`). `width` 가 **화면 픽셀**이라, 카메라를
   멀리 빼면 글자에 비해 외곽선이 굵어진다. 또 SDF 는 64 px 로 한 번만 뜨고 FreeType SDF 의 기본 퍼짐은 8 px 이다(`[가정]` 기본값,
   `EnsureGlyph` 가 퍼짐을 설정하지 않는다). 32 px 글자를 1:1 로 보면 표현 가능한 외곽선은 약 8 × 32/64 = 4 px 인데 입력은
   64 까지 받는다(`TextRenderSystem.cpp:661`). 문턱이 0 아래로 가면 쿼드 전체가 외곽선 색이 되어 **글자마다 사각형이 보인다.**
8. **64 px SDF 아틀라스는 한국어에서 페이지가 빨리 늘어난다.** (추정)
   음절 하나가 64 px 에서 대략 56~60 px 이고 퍼짐 8 px 가 양쪽에 붙으면 약 73 x 77 칸이다. 1024² 한 장에 약 14 x 13 ≈ 180 자가 들어간다.
   대사가 있는 한국어 게임은 서로 다른 음절 수백 ~ 천여 개를 쓰므로 face 하나에 페이지가 3~8 장 생기고, 한 문자열이 여러 페이지를
   쓰면 페이지마다 드로가 나뉜다. 페이지마다 RGBA8 이라 4 MB 이고, 실제로 쓰는 채널은 하나다.
9. **폰트 패밀리 자산과 폴백 체인이 1 판 범위에 비해 무겁다.** (설계 판단)
   리치 텍스트가 제외 범위인데도 `FontStyle` 과 스타일별 face, 패밀리 안의 폴백 목록, 프로젝트 폴백, 순환 방문 검사(`AppendFamilyFaces`)까지
   있었다. 한 텍스트가 한 스타일만 쓴다면 "Bold face 를 직접 고른다" 로 같은 결과가 나온다. 패밀리 자산은 리치 텍스트(한 문자열 안에서
   굵게 전환)가 들어올 때 비로소 값어치가 생긴다.
10. **글리프 생성이 메인 스레드에서 동기로 돈다.** (코드로 확인, 비용은 추정)
    FreeType 의 SDF 래스터라이저는 비트맵보다 훨씬 비싸다. 처음 보는 음절이 많은 대사 한 줄이 한 프레임에 몰리면 끊긴다.
    제외 범위에 "비동기 glyph 생성" 이 있었으므로 알고 미룬 것이다.

## 3. 구조를 깨트려 본 갈림길

기존 모양을 기본값으로 두지 않고, 갈림길마다 반례를 먼저 세웠다. 각 항목 끝의 권고는 2026-09-25 에 모두 확인돼 D-200 이 됐다.

### 3.1 문자열은 어디에 사나 (가장 먼저 풀어야 한다)

기존의 `String Text` 는 D-51 에 막힌다. 막는 이유가 실제로 있다: 스크립트 DLL 이 `text = "..."` 로 대입하면 DLL 쪽 할당기로
메모리를 잡고, 호스트가 풀에서 파기할 때 호스트 쪽 할당기로 푼다(`Allocator.h:40~44` 가 "다른 모듈이 만든 저장소를 이 모듈의
연산으로 해제하면 안 된다" 고 적었다).

- (a) **호스트 소유 저장소 + 핸들.** 컴포넌트에는 `TextId`(번호 + 세대, POD)만 둔다. 글자는 텍스트 시스템의 저장소가 들고,
  스크립트는 `Text2DService::SetText(handle, const char* utf8, std::uint32_t length)` 로 바꾼다(기존 설계 문서도 DLL 경계의 문자열
  API 를 `(const char*, length)` 입력으로 적었다). 저장소가 쓸 때마다 세대를 올리므로 **변경 감지가 정수 비교 하나**가 되어 §1.2 의
  4 번이 사라진다. 에디터는 커맨드로 같은 저장소를 고치고, 캔버스 파일에는 글자로 적는다.
- (b) **컴포넌트 안의 고정 버퍼**(`char text[256]`). POD 라 단순하지만 길이가 묶이고 컴포넌트가 256 B 커진다. 대사 한 문단이 넘친다.
- (c) **D-51 에 예외를 둔다.** 가장 싸지만 결정 하나를 되돌리는 일이고, 할당기 불일치는 CRT 설정에 따라 조용히 숨는다.

권고 `[결정 D-200]`: (a). 뒤에 로컬라이징이 오면 같은 자리에 "키로 가리키는 글자" 를 더할 수 있다(`textKey: NameId`).

### 3.2 누가 무엇을 하나 - 한 덩어리 렌더 시스템인가

기존은 폰트 로드·셰이핑·레이아웃·아틀라스·메시·재료·제출·경계 되쓰기가 `CTextRenderSystem` 하나에 있었다. 반례: 레이아웃이 맞는지
재려면 캔버스와 RHI 를 세워야 했다. 물리(D-199)와 네트워크(D-122)는 같은 이유로 캔버스를 모르는 커널을 따로 두었다.

권고 `[결정 D-200]`: 커널 모듈 `JBroText`(Tier E)를 두고 **폰트 face·셰이핑·줄바꿈·레이아웃·아틀라스 채우기(CPU 픽셀)** 를 거기에 둔다.
입력은 UTF-8 과 레이아웃 옵션, 출력은 POD 글리프 배열(위치·크기·아틀라스 칸·페이지)과 경계다. 캔버스·컴포넌트·렌더러를 모른다.
Framework2DSystem 의 `Text2DSystem` 은 어댑터로서 저장소 세대 비교 → 커널 레이아웃 → 아틀라스 텍스처 올리기 → 스프라이트 아이템 제출만 한다.
경계는 시스템의 캐시(키는 `InstanceId`)가 들고 에디터가 그것을 묻는다. **컴포넌트에 되쓰지 않는다**(§1.2 의 5·6 번).

### 3.3 텍스트마다 메시인가, 글자마다 인스턴스인가

기존은 텍스트마다 정점 버퍼를 만들었다. 새 렌더러는 이미 **단위 쿼드 인스턴싱**이라, 글자 하나를 `SpriteRenderItem` 하나로 보내면
UV 사각형(D-113)과 틴트와 정렬이 그대로 쓰인다. GPU 버퍼를 만들 일이 없다.

반례로 세운 것과 답:
- **정렬 안정성**: 한 텍스트의 글자들은 `sourceId` 가 같아 서로의 순서가 정해지지 않는다. 겹치지 않는 채우기 글자는 상관없지만
  4 단계의 외곽선이 이웃 글자에 겹칠 수 있다. 정렬 키의 예약 16 비트(`[15:0]`)에 글자 순번을 넣으면 된다(65,536 자까지).
- **제출 용량**: `RenderWorld2D` 는 예약 용량을 넘으면 떨어뜨린다(`SubmitSprite`). 글자 2,000 자짜리 텍스트는 스프라이트 예산을
  그만큼 먹는다. 용량 산정에 텍스트 글자 수를 더해야 한다 `[열림]`.
- **인스턴스 크기**: 40 B × 글자 수. 1 만 자여도 400 KB 라 문제가 아니다.

권고 `[결정 D-200]`: 글자마다 스프라이트 인스턴스. 4 단계에서 SDF 셰이더가 필요해지면 `SpriteSubmit` 에 파이프라인 종류와 외곽선
값을 더한다(§4.5). 텍스트용 제출 목록을 따로 두면 같은 레이어 안에서 스프라이트와 텍스트를 섞어 정렬할 수 없으므로 두지 않는다.

### 3.4 FreeType + HarfBuzz 인가, stb_truetype 인가

§1.2 의 1 번대로라면 기존 엔진은 HarfBuzz 의 값어치(GPOS 커닝·GSUB 합자·복잡한 문자 체계)를 쓰지 않았다. 범위가 한글·라틴이면:

| | FreeType 2.13 + HarfBuzz 12 | stb_truetype 1.26 (단일 헤더) |
|---|---|---|
| 크기 | 소스 수십만 줄, 빌드 단위 둘 | 헤더 하나, 5,000 줄 남짓. ImGui 가 이미 사본을 빌드한다 |
| TTF·OTF(CFF) | 둘 다 | 둘 다(`imstb_truetype.h:1304·1417`) |
| 커닝 | GPOS 전부(HarfBuzz) | `kern` 표 + GPOS 쌍 조정(1.19 부터, `:2501`). 클래스 쌍까지 |
| 합자·결합 문자 위치(GPOS mark) | 된다 | 안 된다 |
| 힌팅(작은 글자 선명도) | 된다 | 없다 |
| SDF | `FT_RENDER_MODE_SDF` | `stbtt_GetGlyphSDF`(`:953`) |
| 복잡한 문자 체계(아랍·인도계) | 된다 | 안 된다 |

반례로 세운 것과 답:
- **분해된 한글(NFD, macOS 파일 이름 등)**: 자모 조합은 GSUB 없이도 산술로 된다(`0xAC00 + (L×21 + V)×28 + T`). 입력을 음절로
  정규화하면 stb 로도 맞게 나온다. 옛한글·조합 불가 자모는 못 한다.
- **라틴 결합 문자(`e` + U+0301)**: stb 는 위치를 못 잡는다. 흔한 조합은 NFC 로 미리 합칠 수 있지만 표가 필요하다. 입력이 대부분
  미리 합쳐진 형태라 드문 경우다.
- **작은 글자**: 힌팅이 없으면 12~14 px 한글이 흐리다. 2D 게임 UI 에서 실제로 보이는 차이다. 픽셀 폰트(비트맵 폰트 파일)는 힌팅과 무관하다.
- **나중에 바꾸는 비용**: 커널의 face·셰이핑 표면을 우리 타입으로 닫아 두면, 라이브러리를 바꿀 때 커널 안만 바뀐다.

권고 `[결정 D-200]`: **1 판은 stb_truetype.** `ThirdParty/stb/stb_truetype.h` 로 정식 사본을 넣는다(ImGui 의 `imstb_` 사본은 ImGui 의
것이라 가져다 쓰지 않는다, ThirdParty 규칙). 커널 표면을 라이브러리와 무관하게 닫아서, 작은 글자 품질이나 복잡한 문자 체계가
필요해지면 FreeType + HarfBuzz 로 커널 안만 바꾼다. 이 판단은 §6 의 질문 2 로 확인받는다.

### 3.5 SDF 한 벌인가, 모드를 고르나

프로젝트 기본 필터가 Nearest(D-119)라는 것은 이 엔진이 픽셀 아트 2D 를 기본으로 본다는 뜻이다. 픽셀 폰트에 SDF 를 쓰면
모서리가 둥글어지고, Linear 샘플링이 필요해 픽셀 격자가 흐려진다. 반대로 확대·축소가 잦은 HD 텍스트는 비트맵이면 크기마다 아틀라스를 새로 떠야 한다.

권고 `[결정 D-200]`: 폰트 에셋 임포트 옵션에 `renderMode { Bitmap, Sdf }` 를 둔다.
- `Bitmap`: (face, 픽셀 크기) 마다 커버리지 아틀라스. RGBA8 에 `(255, 255, 255, 커버리지)` 로 적으면 **지금 스프라이트 셰이더(`texture * tint`)
  가 그대로 그린다.** 필터는 에셋의 텍스처 필터를 따른다. 외곽선은 없다(1 판).
- `Sdf`: face 마다 한 벌. **뜨는 크기를 64 가 아니라 32~48 로** 두고 퍼짐을 임포트 옵션으로 연다. 외곽선 상한은 퍼짐이 정하므로
  입력 폭을 그 값으로 자르고, 폭 단위는 화면 픽셀이 아니라 **글자 픽셀**로 한다(§1.2 의 7 번). 전용 셰이더가 필요하다(4 단계).

### 3.6 아틀라스를 언제 어떻게 올리나

지금 RHI 는 전체 텍스처 쓰기만 되고 GPU 를 기다린다. 새 글자가 생길 때마다 1024² RGBA8(4 MB)을 올리고 멈추면, 대사를 한 글자씩
찍는 연출에서 음절마다 끊긴다.

- 1 단계: 시스템 Update(렌더러 프레임 밖)에서 **그 프레임에 새로 생긴 글자를 모아 한 번만** 올린다. 비용을 실측한다.
- 임포트 옵션 `prewarm { None, Ascii, Ksx1001 }`: KS X 1001 의 한글 2,350 자를 미리 채우면 대부분의 한국어 게임 텍스트가 런타임
  래스터화 없이 그려진다. 32 px 비트맵이면 대략 2,350 × 36² ≈ 3 M 픽셀이라 1024² 세 장쯤이다(추정). `.jpak` 익스포트가 서면 미리 뜬
  아틀라스를 패키지에 넣어 게임 실행이 폰트 래스터화를 하지 않게 할 수 있다 `[열림]`.
- 부분 영역 쓰기(`WriteTexture` 에 사각형)와 R8 포맷은 RHI 세 백엔드의 일이라 따로 둔다 `[열림]`. 필요하다는 실측이 나오면 연다.

### 3.7 패밀리·스타일·폴백

권고 `[결정 D-200]`: 1 판은 **`Font` 에셋 하나(= face 하나)** 만 둔다. `Text2D::fontId` 가 그것을 가리키고, 비어 있으면 프로젝트 기본 폰트다.
폴백은 **프로젝트 설정의 순서 있는 폰트 목록 하나**다(한글 폰트에 없는 이모지·기호를 다른 폰트에서 찾는 용도). 패밀리 자산, `FontStyle`,
패밀리 안 폴백, 순환 검사는 리치 텍스트가 들어올 때 다시 본다 `[열림]`.

### 3.8 셰이핑 단위와 줄바꿈

- 같은 폰트가 이어지는 **줄 안의 구간 전체**에 커닝을 적용한다(stb 는 이웃 글리프 쌍마다 `stbtt_GetGlyphKernAdvance`).
- 줄바꿈 기회: 공백 뒤, 한글·한자·가나 음절 사이, 명시적 개행. 폭을 넘으면 마지막 기회로 되돌아가고, 기회가 없는 긴 단어는 글자에서 끊는다.
  `wrapMode { Word, Character }` 에서 `Word` 는 한글도 어절 단위(공백)로만 끊는다. 기본값은 `Word` 다(D-200 (5), §6).
- CRLF·CR 은 LF 로 본다. 잘못된 UTF-8 은 U+FFFD 로 바꾼다(기존과 같다). 정규화 사본을 만들지 않고 읽으면서 처리한다.

## 4. 설계 (D-200)

### 4.1 계층

```
Tier S  JBroAssetTypes        Asset::Font (메타·임포트 옵션: renderMode · pixelSize · sdfSpread · pixelsPerUnit · prewarm)
Tier S  JBroFramework2D       Component::Text2D (저작 값 + TextId) · Service::Text2DService (SetText · GetText 길이/복사)
           ▲
Tier E  JBroText (새)         캔버스를 모르는 커널: FontFace(stb) · Shaper(커닝) · LineBreaker · Layout · GlyphAtlas(CPU 픽셀, 선반 할당)
           ▲
Tier E  JBroAsset             Font 로더(바이트 소유, ReloadInPlace 때 세대 증가)
Tier E  JBroFramework2DSystem Text2DSystem = 어댑터: 저장소 세대 비교 → 레이아웃 → 아틀라스 업로드 → 글자마다 SpriteRenderItem
                              TextStore(호스트 소유 UTF-8 저장소, TextId 발급)
```

- 커널은 `JBroCore` 만 쓴다. `Vec2` 가 필요하면 물리 커널(D-199)처럼 `Math2D.h` 만 본다. 의존하지 않은 헤더를 include 하면 실패하는
  음성 테스트로 지킨다. 3D 텍스트가 오면 같은 커널을 쓴다.
- 커널의 식별자는 번호다(face 번호, 아틀라스 페이지 번호). `SafePtr` 는 커널에 들어가지 않는다.

### 4.2 컴포넌트 `Text2D`

저작 값만 둔다. 이름은 기존을 따르되 현재 규칙(접두사 없음, 소문자 시작 필드)에 맞춘다.

| 필드 | 형 | 비고 |
|---|---|---|
| `text` | `TextId` | 저장소 핸들. 인스펙터는 여러 줄 입력 칸으로 보이고, 캔버스 파일에는 글자로 적힌다 |
| `fontId` | `AssetId` | 비면 프로젝트 기본. `Id` 로 끝나므로 에셋 해석 패스와 `AssetField` 가 그대로 붙는다(D-115·D-118) |
| `fontSize` | `float` | 글자 픽셀. 유닛 크기는 폰트 에셋 PPU 로 나눈다(D-119 와 같은 규칙) |
| `boxSize` | `Vec2` | 글자 픽셀. 0 이면 무제한 |
| `overflow` | `enum { Overflow, Wrap, Clip }` | 기존과 같다 |
| `wrapMode` | `enum { Word, Character }` | §3.8 |
| `alignX`·`alignY` | `enum` | Left·Center·Right / Top·Middle·Baseline·Bottom |
| `lineSpacing`·`letterSpacing` | `float` | |
| `color` | `Color` | 채우기 |
| `outlineColor`·`outlineWidth` | `Color`·`float` | Sdf 폰트에서만 쓰인다(4 단계). 폭은 글자 픽셀 |
| `renderOrder` | `int32` | `SpriteRenderer2D` 와 같은 뜻 |
| `pixelSnap` | `bool` | |

자동 크기(Min~Max)는 1 판에서 뺀다 `[열림]`. 필요해지면 캐시한 레이아웃의 줄 폭으로 이진 탐색을 하되, 탐색 중 할당이 없게 한다.

### 4.3 저장소와 변경 감지

- ~~`TextStore` 는 캔버스마다 하나이고 Framework2DSystem 이 든다~~ → **프로세스에 하나이고 `JBroRuntime` 이 든다(D-211)**. 코덱이 문맥을 받지
  않고, 캔버스가 시스템을 오브젝트보다 먼저 내리기 때문이다. 슬롯은 `{ String utf8, generation, revision }`, 핸들은 `번호 + 세대`.
- 컴포넌트가 붙을 때 슬롯을 받고 떨어질 때 돌려준다. 캔버스 파일을 읽을 때 글자를 슬롯에 넣는다. 복사·붙여넣기·프리팹은 글자를 복사해 새 슬롯을 받는다.
- 시스템 캐시(키 `InstanceId`)는 `(text 세대, 폰트 핸들 세대, 레이아웃 옵션 해시)` 가 같으면 레이아웃을 건너뛴다. 옵션 해시는 필드 몇 개의
  정수·실수 결합이라 글자 수와 무관하다.
- **글자가 바뀐 텍스트의 레이아웃은 매 프레임 할당 없이 돈다**: 캐시마다 글리프 배열 용량을 들고 `Clear` 로 다시 쓴다.

### 4.4 아틀라스

- `GlyphAtlas` 는 CPU 픽셀(RGBA8)과 선반 할당기와 "더러운 페이지" 표시를 든다. 키는 `(face, 픽셀 크기 또는 Sdf, 글리프 번호)`.
- 페이지는 1024² 로 시작한다. 가득 차면 새 페이지를 만들고 옛 칸을 옮기지 않는다(기존과 같다, UV 가 고정된다).
- 시스템은 레이아웃이 끝난 뒤 더러운 페이지만 `Renderer::UpdateTexture` 로 올린다(프레임 밖). 첫 판은 페이지 전체를 올린다.
- 비우기는 폰트가 재로드될 때(세대가 바뀔 때)만 한다. 오래 안 쓴 글자의 퇴출은 `[열림]`.

### 4.5 렌더러 (4 단계에서만 바뀐다)

- `SpriteSubmit` 과 `SpriteRenderItem` 에 `shading { Sprite, SdfText }` 와 `outlineColor`·`sdfParams(퍼짐 대비 문턱)` 를 더한다.
  렌더러는 같은 (파이프라인, 텍스처, 필터) 가 이어지는 구간을 한 드로로 묶는다. 인스턴스 레이아웃이 커지므로 스프라이트 전체가 영향을 받는다 -
  `GpuSpriteInstance` 를 둘로 나눌지(텍스트 전용 인스턴스 버퍼) 한 벌로 키울지는 4 단계 시작 때 실측으로 정한다 `[열림]`.
- SDF 셰이더는 기존 식을 이어받되, 폭을 `fwidth` 곱이 아니라 퍼짐 대비 비율(글자 픽셀)로 넣고 문턱을 0 이상으로 자른다.

### 4.6 에디터

- 인스펙터: `text` 는 여러 줄 글자 칸 위젯(새 `Widget::TextArea`, §11.1 대로 위젯 계층), 편집은 커맨드 하나(되살릴 값 = 옛 글자).
- 캔버스 뷰: 시스템 캐시의 경계로 선택·외곽선. 캐시가 없으면(폰트 없음) 경고 표시와 작은 기본 상자.
- 에셋 브라우저: `.ttf`·`.otf` 가 `Font` 로 등록되고, 인스펙터에 임포트 옵션이 뜬다(D-120 과 같은 모양).

### 4.7 스크립트

`Text2DService` 는 `Physics2DService` 처럼 `Framework2DServiceContext` 를 거친다(D-42·D-43). `SetText(Ref<Text2D>, const char* utf8, uint32 length)`,
`GetTextLength`, `CopyText(buffer, capacity)`. 입력은 POD 이고 호스트가 복사한다. 숫자 표시처럼 자주 바뀌는 것을 위해
`SetTextFormat` 류는 두지 않는다 - 스크립트가 자기 버퍼에 쓰고 `SetText` 를 부르면 된다.
